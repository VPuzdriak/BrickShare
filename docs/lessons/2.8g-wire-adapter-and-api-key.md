# Lesson 2.8g. Wire the adapter: typed `HttpClient`, standard resilience handler, API key in user secrets

Features: [F01](../features/01-catalog-management.md#lookup-in-rebrickable)
Previous: [2.8f](2.8f-rebrickable-unavailable-domain-exception.md) · Next: [2.8h](2.8h-lookup-set-draft.md)

## Summary

We register the adapter in the Api host. The host gets a typed `HttpClient` with the Rebrickable base URL and the API key in the `Authorization` header. The standard resilience handler retries failures, limits each attempt and the whole call, and opens a circuit breaker. You set each of these in code. You store your own Rebrickable key in user secrets. At the end the Catalog host starts with the adapter, and the existing tests are green.

## The problem

[Architecture.md section 3.2](../Architecture.md#32-catalog-service) says: "a typed `HttpClient` for Rebrickable API v3... with the standard resilience handler. It sends the API key in the `Authorization: key <key>` header." The key is a secret. It must not be in the repository, and the base URL is public. Azure reads the key from Key Vault later, through managed identity ([Architecture.md section 5.4](../Architecture.md#54-service-identities)). On your machine, user secrets hold it.

## Step 4. Catch the resilience exceptions in the adapter

The standard handler can end a call with a timeout or with an open circuit. Microsoft's [HTTP resilience guide](https://learn.microsoft.com/dotnet/core/resilience/http-resilience) lists `HttpRequestException` and `TimeoutRejectedException`. An open circuit throws `BrokenCircuitException`. Catch all three, so the caller always gets the domain exception.

`src/Services/Catalog/BrickShare.Catalog.Api/Infrastructure/Rebrickable/RebrickableSetSpecificationProvider.cs` (replace the `catch` clause, and add two `using` lines)

Add these `using` lines at the top, next to the others:

```csharp
using Polly.CircuitBreaker;
using Polly.Timeout;
```

Before:

```csharp
        catch (HttpRequestException exception)
        {
            throw new SetSpecificationUnavailableException("Rebrickable is unavailable.", exception);
        }
```

After:

```csharp
        catch (Exception exception) when (exception is HttpRequestException or TimeoutRejectedException or BrokenCircuitException)
        {
            throw new SetSpecificationUnavailableException("Rebrickable is unavailable.", exception);
        }
```

The `Polly` namespaces come with the package from step 3. If the compiler does not find `Polly.CircuitBreaker` or `Polly.Timeout`, the namespace name in your package version differs. Find the exception type in your IDE and fix the `using` line. Do not remove the clause.

## Step 5. Register the adapter

We create the registration class with the CLI. Run from the repository root:

```powershell
dotnet new class -n RebrickableRegistration -o src/Services/Catalog/BrickShare.Catalog.Api/Infrastructure/Rebrickable
```

`src/Services/Catalog/BrickShare.Catalog.Api/Infrastructure/Rebrickable/RebrickableRegistration.cs` (replace the template class with this content)

```csharp
using System;
using System.Net.Http.Headers;

using BrickShare.Catalog.Domain;

using Microsoft.Extensions.Configuration;
using Microsoft.Extensions.DependencyInjection;

namespace BrickShare.Catalog.Api.Infrastructure.Rebrickable;

public static class RebrickableRegistration
{
    public static IServiceCollection AddRebrickableLookup(this IServiceCollection services, IConfiguration configuration)
    {
        var rebrickable = configuration.GetSection("Rebrickable");

        var baseUrl = rebrickable["BaseUrl"]
            ?? throw new InvalidOperationException("The setting 'Rebrickable:BaseUrl' is missing.");

        var apiKey = rebrickable["ApiKey"]
            ?? throw new InvalidOperationException("The setting 'Rebrickable:ApiKey' is missing. Set it with dotnet user-secrets.");

        services.AddHttpClient<ISetSpecificationProvider, RebrickableSetSpecificationProvider>(client =>
            {
                client.BaseAddress = new Uri(baseUrl);
                client.DefaultRequestHeaders.Authorization = new AuthenticationHeaderValue("key", apiKey);
            })
            .AddStandardResilienceHandler(options =>
            {
                options.Retry.MaxRetryAttempts = 2;
                options.AttemptTimeout.Timeout = TimeSpan.FromSeconds(5);
                options.TotalRequestTimeout.Timeout = TimeSpan.FromSeconds(30);
                options.CircuitBreaker.FailureRatio = 0.5;
                options.CircuitBreaker.MinimumThroughput = 5;
                options.CircuitBreaker.SamplingDuration = TimeSpan.FromSeconds(30);
                options.CircuitBreaker.BreakDuration = TimeSpan.FromSeconds(15);
            });

        return services;
    }
}
```

### Control timeouts, retries, and the circuit breaker

The options lambda in the registration sets the standard handler. The handler applies the settings to every request the adapter makes. The table lists each setting, its default, and the value this lesson uses.

| Setting | What it controls | Default | Value here |
|---------|------------------|---------|------------|
| `Retry.MaxRetryAttempts` | Retries after the first call. A transient failure is retried with exponential backoff and jitter. | 3 | 2 |
| `Retry.Delay` | Base delay between attempts. Not set in the code. | 2 s | 2 s (default) |
| `AttemptTimeout.Timeout` | Time limit for one attempt. | 10 s | 5 s |
| `TotalRequestTimeout.Timeout` | Time limit for the whole call, retries included. | 30 s | 30 s |
| `CircuitBreaker.FailureRatio` | Share of failed calls in the sampling window that opens the circuit. | See the [API reference](https://learn.microsoft.com/dotnet/api/microsoft.extensions.http.resilience.httpstandardresilienceoptions) | 0.5 |
| `CircuitBreaker.MinimumThroughput` | Calls needed in the window before the ratio counts. | See the API reference | 5 |
| `CircuitBreaker.SamplingDuration` | Length of the window that the ratio is measured over. | See the API reference | 30 s |
| `CircuitBreaker.BreakDuration` | How long the circuit stays open before a trial call. | See the API reference | 15 s |

When the circuit is open, calls fail at once with `BrokenCircuitException`. Lesson 2.8g's step 4 catches it, so the caller still gets `SetSpecificationUnavailableException`, and the endpoint answers `503`.

Three rules matter when you change these values:

- **The total timeout must cover all attempts.** Two retries at 5 s each, plus the delays, stay below the 30 s total. If you raise the attempt timeout, raise the total too.
- **The sampling window must be longer than the attempt timeout.** The handler checks this when the app starts. A window shorter than twice the attempt timeout is rejected.
- **Retries multiply the calls.** One lookup makes up to four Rebrickable calls. With two retries, each call can make three attempts, so one lookup can send up to twelve requests in a burst. [Architecture.md section 3.2](../Architecture.md#32-catalog-service) asks for about one request per second. Keep the retry count low for this reason.

The settings are code, not configuration, so a change needs a build and a deploy. If you want them in `appsettings.json` later, bind them with the options pattern. That is not part of this lesson.

Next, the base URL goes into `appsettings.json`. It is public, so it does not need a secret store.

`src/Services/Catalog/BrickShare.Catalog.Api/appsettings.json` (add this section as the first member of the top-level object)

```json

    "BaseUrl": "https://rebrickable.com/"

```

## Step 7. Store the API key in user secrets

Run from the repository root. Replace `<your key>` with the key from step 1. The quotes keep the key intact in PowerShell:

```powershell
dotnet user-secrets set "Rebrickable:ApiKey" "<your key>" --project src/Services/Catalog/BrickShare.Catalog.Api
```

Check that it is stored. The output shows the key name, and the value is masked by the tool's list output:

```powershell
dotnet user-secrets list --project src/Services/Catalog/BrickShare.Catalog.Api
```

Expected: a line `Rebrickable:ApiKey = <your key>`. The user secrets file lives outside the repository, so Git never sees it.

Without the key, the host stops at start with "The setting 'Rebrickable:ApiKey' is missing". That message is the expected result when the key is not set.
