# Lesson 2.8d. Adapter: unknown set returns `null`, test-first

Features: [F01](../features/01-catalog-management.md#lookup-in-rebrickable)
Previous: [2.8c](2.8c-specification-port-and-adapter.md) · Next: [2.8e](2.8e-specification-cache.md)

## Summary

The adapter returns `null` when Rebrickable does not know the set. Any other failure still throws. The caller turns `null` into `404` in lesson 2.8i. At the end the adapter has two green tests.

## The problem

[Catalog management](../features/01-catalog-management.md#lookup-in-rebrickable) says: "A set number unknown to Rebrickable returns `404`." Rebrickable answers `404` for an unknown set. The adapter must tell "unknown set" apart from "Rebrickable is broken". `null` means unknown. A thrown exception means a failure.

## Step 3. Green: a `404` means "unknown set"

`GetAsync` returns `null` for `404`. A new helper `GetRequiredAsync` throws for `null`, and the minifigure and theme calls use it, because a set that exists must have them.

`src/Services/Catalog/BrickShare.Catalog.Api/Infrastructure/Rebrickable/RebrickableSetSpecificationProvider.cs` (replace the `GetAsync` method, and add `using System.Net;` at the top)

Before:

```csharp
    private async Task<T> GetAsync<T>(string path, CancellationToken cancellationToken) where T : class
    {
        using var response = await httpClient.GetAsync(path, cancellationToken);
        response.EnsureSuccessStatusCode();

        return await response.Content.ReadFromJsonAsync<T>(JsonOptions, cancellationToken)
            ?? throw new HttpRequestException($"Rebrickable returned an empty body for {path}.");
    }
```

After:

```csharp
    private async Task<T?> GetAsync<T>(string path, CancellationToken cancellationToken) where T : class
    {
        using var response = await httpClient.GetAsync(path, cancellationToken);

        if (response.StatusCode == HttpStatusCode.NotFound)
        {
            return null;
        }

        response.EnsureSuccessStatusCode();

        return await response.Content.ReadFromJsonAsync<T>(JsonOptions, cancellationToken);
    }

    private async Task<T> GetRequiredAsync<T>(string path, CancellationToken cancellationToken) where T : class =>
        await GetAsync<T>(path, cancellationToken)
        ?? throw new HttpRequestException($"Rebrickable has no resource at {path}.");
```

`src/Services/Catalog/BrickShare.Catalog.Api/Infrastructure/Rebrickable/RebrickableSetSpecificationProvider.cs` (replace the whole `FindAsync` method)

```csharp
    public async Task<SetSpecification?> FindAsync(RebrickableSetNumber setNumber, CancellationToken cancellationToken)
    {
        var setResponse = await GetAsync<SetResponse>($"api/v3/lego/sets/{setNumber.Value}/", cancellationToken);

        if (setResponse is null)
        {
            return null;
        }

        var minifigs = await GetRequiredAsync<MinifigsResponse>($"api/v3/lego/sets/{setNumber.Value}/minifigs/", cancellationToken);
        var theme = await LoadThemeAsync(setResponse.ThemeId, cancellationToken);

        return new SetSpecification(
            setNumber,
            setResponse.Name,
            setResponse.Year,
            setResponse.NumParts,
            minifigs.Count,
            theme,
            setResponse.SetImgUrl is null ? null : new Uri(setResponse.SetImgUrl),
            new Uri(setResponse.SetUrl));
    }
```

In `LoadThemeAsync`, the theme must exist, so it uses the required helper.
