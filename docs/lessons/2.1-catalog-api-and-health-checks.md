# Lesson 2.1. Catalog Api project and liveness check

Previous: [1.11](1.11-github-repository-setup.md) · Next: 2.2 Catalog Domain project, `LegoSet` aggregate and value objects, test-first

## Summary

We create the `BrickShare.Catalog.Api` project, the first ASP.NET Core project of the Catalog Service. It serves an OpenAPI document and the Scalar UI. It also has a liveness check at `/health/live` that answers without checking any dependency. At the end the Api starts, and the three URLs answer as described below.

## The problem

The repository has shared building blocks and tests, but no running service. Without an Api project:

- Nothing answers HTTP, so the Catalog Service cannot be started, deployed, or probed. [Architecture.md section 7.5](../Architecture.md#75-containers) and [section 8](../Architecture.md#8-local-development) assume a running service in every container.
- The hosting platforms need a health endpoint. [Architecture.md section 11](../Architecture.md#11-cross-cutting-concerns) defines `/health/live` and `/health/ready`. Readiness checks come in lesson 12.3. The liveness check comes first. Container Apps and App Service probe it. It must not call a database, so that a database outage does not restart the process.
- Each API must expose OpenAPI and a Scalar UI for testing. [Architecture.md section 1.3](../Architecture.md#13-scope-and-assumptions) requires this for every API.

No feature rule in [docs/features/](../features/README.md) drives this lesson. The business rules of Catalog arrive in lesson 2.2 and later. This lesson builds the host that they plug into.

The concepts:

- **Minimal API host.** [CLAUDE.md](../../CLAUDE.md) requires Minimal APIs and no MVC controllers. The host is one `Program.cs` file. Endpoints are added as slices later.
- **Liveness.** A liveness check answers "is the process up?". A readiness check answers "can the process serve traffic?". Only readiness checks dependencies. In this lesson the check runs no checks at all, so it answers `Healthy` whenever the process runs.
- **Explicit authorization.** [CLAUDE.md](../../CLAUDE.md) requires an authorization policy on every endpoint group from the start. The health endpoint is public, so it declares `AllowAnonymous` on purpose.

## Step 2. Create the Catalog Api project

We create an ASP.NET Core project with the `web` template. The template writes its own target framework and implicit usings. The repository sets the target framework in `Directory.Build.props`, and the course uses explicit `using` lines. So we adjust the project file by hand. The project lives under `src/Services/Catalog/`, the folder from [Architecture.md section 7](../Architecture.md#7-solution-structure).

Run from the repository root:

```powershell
dotnet new web -n BrickShare.Catalog.Api -o src/Services/Catalog/BrickShare.Catalog.Api
dotnet sln BrickShare.slnx add src/Services/Catalog/BrickShare.Catalog.Api/BrickShare.Catalog.Api.csproj --solution-folder src/Services/Catalog
```

The template writes a `Program.cs` and a `Properties/launchSettings.json`. We keep the launch settings and replace `Program.cs` in step 4.

Then add the two packages. `Microsoft.AspNetCore.OpenApi` produces the OpenAPI document, and `Scalar.AspNetCore` serves the Scalar UI on top of it. The solution targets .NET 10, and lesson 17.1 moves it to .NET 11 later. So pin `Microsoft.AspNetCore.OpenApi` to a 10.0.x version. Look up the newest one first:

```powershell
dotnet package search Microsoft.AspNetCore.OpenApi --exact-match
```

Then, with the newest `10.0.x` version from the output in place of `<newest 10.0.x>`:

```powershell
dotnet add src/Services/Catalog/BrickShare.Catalog.Api package Microsoft.AspNetCore.OpenApi --version <newest 10.0.x>
dotnet add src/Services/Catalog/BrickShare.Catalog.Api package Scalar.AspNetCore
```

The CLI writes the versions into `Directory.Packages.props`. The project file gets the items without a `Version`.

`src/Services/Catalog/BrickShare.Catalog.Api/BrickShare.Catalog.Api.csproj` should read as follows. Remove the template's `TargetFramework`, `ImplicitUsings`, and `Nullable` lines. The packages come from the commands above, and the file keeps only these items:

```xml
<Project Sdk="Microsoft.NET.Sdk.Web">

  <ItemGroup>
    <PackageReference Include="Microsoft.AspNetCore.OpenApi" />
    <PackageReference Include="Scalar.AspNetCore" />
  </ItemGroup>

</Project>
```

The project does not build yet, because `Program.cs` still has the template code. That is fixed in step 4, after the health check is in place.

## Step 4. Replace `Program.cs` with the host, OpenAPI, Scalar, and the liveness check

The host has three parts. `AddOpenApi` and `MapOpenApi` publish the OpenAPI document. `MapScalarApiReference` serves the UI for it. `MapHealthChecks` serves the liveness check. The check gets an empty predicate, so it runs no registered check and answers `Healthy` while the process is up. Readiness checks for the database and Service Bus come in lesson 12.3, on a separate `/health/ready` route.

The health endpoint calls `AllowAnonymous()`, because a probe from the platform carries no token. The rest of the Api has no endpoints yet, so no other group needs a policy.

`src/Services/Catalog/BrickShare.Catalog.Api/Program.cs` (replace the template file with this content)

Before: the template's sample `app.MapGet("/", ...)` and its `WebApplication` setup.

After:

```csharp
using Microsoft.AspNetCore.Builder;
using Microsoft.AspNetCore.Diagnostics.HealthChecks;
using Microsoft.Extensions.DependencyInjection;
using Scalar.AspNetCore;

var builder = WebApplication.CreateBuilder(args);

builder.Services.AddOpenApi();
builder.Services.AddHealthChecks();

var app = builder.Build();

app.MapOpenApi();
app.MapScalarApiReference();

app.MapHealthChecks("/health/live", new HealthCheckOptions { Predicate = _ => false })
    .AllowAnonymous();

await app.RunAsync();
```

`AddHealthChecks` registers the health check services. The empty predicate selects no registered check, so the response depends only on the process. The `using` lines are explicit because the Api project does not use implicit usings. The host awaits `RunAsync` because the SonarAnalyzer rule S6966 asks for it, and warnings are errors.

Run from the repository root:

```powershell
dotnet build BrickShare.slnx
```

Expected: green, with no warnings. The build restores the packages and compiles the host.

## Step 5. Run the Api and call the endpoints

We start the Api and check three URLs. The port comes from the launch profile, so use the address that the console prints.

Run from the repository root:

```powershell
dotnet run --project src/Services/Catalog/BrickShare.Catalog.Api
```

Expected: the console prints `Now listening on: http://localhost:<port>`. Replace `<port>` with that port in each URL:

- `http://localhost:<port>/health/live` returns status `200 OK` and the plain text body `Healthy`.
- `http://localhost:<port>/openapi/v1.json` returns the OpenAPI document. It has no paths yet, so the `paths` object is empty.
- `http://localhost:<port>/scalar/v1` shows the Scalar UI.

Stop the Api with Ctrl+C.
