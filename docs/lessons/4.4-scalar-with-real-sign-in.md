# Lesson 4.4. Scalar with real sign-in

Previous: [4.3](4.3-staff-and-customer-schemes.md) · Next: 5.1 Customer Service projects, `Customer` aggregate, just-in-time provisioning (`/customers/me`)

## Summary

We let staff sign in to the Catalog Service from Scalar. We register a sign-in client, `BrickShare Staff Client`, in the workforce tenant. The OpenAPI document declares an OAuth2 sign-in with the scope `api://<client id>/api.access`, and Scalar uses it to sign in with PKCE. The OpenAPI and Scalar setup sits in two extension methods, `AddApiDocs` and `MapApiDocs`, so `Program.cs` only calls them. At the end, a staff token from a real sign-in gets `200` on the staff probe, `200` on the admin probe for an `Admin` account, and `403` on the customer probe. The Scalar UI is not served in Production.

## The problem

Lesson 4.3 accepts Entra tokens, but no client has sent one yet. Scalar can only test the API with a token that a person got by signing in. Today Scalar has no sign-in. The feature doc and the architecture set the rules:

- "Staff sign in with Microsoft Entra ID (workforce tenant)." ([F04](../features/04-staff-management.md))
- [Architecture 5.1](../Architecture.md#51-tenants-and-app-registrations) names a `BrickShare Staff Client` in the workforce tenant for "Scalar / future staff SPA".
- [Architecture 11](../Architecture.md#11-cross-cutting-concerns) says the Scalar UI is "disabled in Production".

Three gaps block a real sign-in:

- **No client.** Only the API app `BrickShare API` exists (lesson 4.1). Scalar runs in the browser, so it needs its own client. A browser cannot keep a client secret, so the client is a public client that uses PKCE.
- **No scheme in the document.** Scalar pre-fills a sign-in only for a security scheme that the OpenAPI document declares. The document has none today.
- **A bare tenant id.** The `Staff` scheme reads `Authentication:Staff:Authority` as an issuer URL. The repository holds the bare tenant id, which is not a URL. Lesson 4.3 step 9 asks for the URL form. This lesson fixes the value, because the OpenAPI document needs the authority URL too.

The concepts we introduce:

- **Public client with PKCE.** A single-page app has no secret. It sends a code challenge (PKCE) instead, and Entra checks it at the token step.
- **OAuth2 authorization code flow in OpenAPI.** The document names the authorize and token endpoints and the scope. Scalar reads them and opens the sign-in page.
- **Scope in the token.** For the v2 tokens from lesson 4.1, the scope is `api://<client id>/api.access`. Entra puts the client id in the `aud` claim, which matches the `Staff` audience from lesson 4.3.
- **Extension methods for setup.** The OpenAPI and Scalar code is about ten lines of options. Two extension methods keep it out of `Program.cs`. `AddApiDocs` runs with the services, and `MapApiDocs` runs with the endpoints.

Scope decisions:

- **Staff only.** The customer sign-in comes with the Customer Service (module 5). Scalar here signs in only staff.
- **Development only.** The Scalar mapping is skipped in Production, as [Architecture 11](../Architecture.md#11-cross-cutting-concerns) requires. The OpenAPI document stays available, as lesson 2.1 set it up.
- **The UI test checks the document.** The document is plain JSON, so an integration test can check it. The Scalar page itself is a browser UI, so step 8 checks it by hand.

## Step 6. Green: describe the sign-in in the OpenAPI document

The OpenAPI document gets the OAuth2 scheme from a document transformer. The transformer takes the authority and the audience and writes:

- the scheme `oauth2`, of type OAuth2 with the authorization code flow;
- the authorize and token endpoints of the workforce tenant (the v2 endpoints are `oauth2/v2.0/authorize` and `oauth2/v2.0/token` under the tenant);
- the scope `api://<audience>/api.access`;
- a security requirement for the whole document, so Scalar offers the sign-in on every operation.

The transformer is an internal static class in `Infrastructure/Docs`. The class template writes a non-static public class, so both files of this step are written by hand. The transformer uses the OpenAPI types of .NET 10 (`Microsoft.OpenApi`). The project has no implicit usings, so both files list the `System` namespaces they need.

`src/Services/Catalog/BrickShare.Catalog.Api/Infrastructure/Docs/StaffSignInDocument.cs` (new file)

```csharp
using System;
using System.Collections.Generic;
using System.Threading.Tasks;

using Microsoft.AspNetCore.OpenApi;
using Microsoft.OpenApi;

namespace BrickShare.Catalog.Api.Infrastructure.Docs;

internal static class StaffSignInDocument
{
    public const string SchemeName = "oauth2";

    public static string ApiScope(string audience) => $"api://{audience}/api.access";

    public static Task Apply(OpenApiDocument document, string authority, string audience)
    {
        var endpoints = authority.Replace("/v2.0", "/oauth2/v2.0", StringComparison.Ordinal);
        var scope = ApiScope(audience);

        document.Components ??= new OpenApiComponents();
        document.Components.SecuritySchemes ??= new Dictionary<string, IOpenApiSecurityScheme>();
        document.Components.SecuritySchemes[SchemeName] = new OpenApiSecurityScheme
        {
            Type = SecuritySchemeType.OAuth2,
            Flows = new OpenApiOAuthFlows
            {
                AuthorizationCode = new OpenApiOAuthFlow
                {
                    AuthorizationUrl = new Uri($"{endpoints}/authorize"),
                    TokenUrl = new Uri($"{endpoints}/token"),
                    Scopes = new Dictionary<string, string>
                    {
                        [scope] = "Use the BrickShare API as the signed-in staff member."
                    }
                }
            }
        };

        document.Security =
        [
            new OpenApiSecurityRequirement
            {
                [new OpenApiSecuritySchemeReference(SchemeName)] = [scope]
            }
        ];

        document.SetReferenceHostDocument();

        return Task.CompletedTask;
    }
}
```

`ApiScope` is public inside the class because step 7 uses it for the Scalar scopes too. Both places build the scope from the same function, so they cannot drift apart.

`SetReferenceHostDocument` lets the references to the scheme resolve inside the document. It runs last, after the security requirement is set.

Next, the extension methods. `AddApiDocs` reads the two Staff settings, fails when one is missing, and registers the OpenAPI document with the transformer. `MapApiDocs` maps the OpenAPI document, and it maps the Scalar UI outside Production. The Scalar client id is read only in that branch, so a Production start does not need it.

`src/Services/Catalog/BrickShare.Catalog.Api/Infrastructure/Docs/ApiDocsExtensions.cs` (new file)

```csharp
using System;

using Microsoft.AspNetCore.Builder;
using Microsoft.AspNetCore.OpenApi;
using Microsoft.Extensions.Configuration;
using Microsoft.Extensions.DependencyInjection;
using Microsoft.Extensions.Hosting;

using Scalar.AspNetCore;

namespace BrickShare.Catalog.Api.Infrastructure.Docs;

public static class ApiDocsExtensions
{
    public static IServiceCollection AddApiDocs(this IServiceCollection services, IConfiguration configuration)
    {
        var (authority, audience) = ReadStaffSettings(configuration);

        return services.AddOpenApi(options =>
            options.AddDocumentTransformer((document, _, _) =>
                StaffSignInDocument.Apply(document, authority, audience)));
    }

    public static WebApplication MapApiDocs(this WebApplication app)
    {
        app.MapOpenApi();

        if (app.Environment.IsProduction())
        {
            return app;
        }

        var (_, audience) = ReadStaffSettings(app.Configuration);
        var clientId = app.Configuration["Scalar:StaffClientId"]
            ?? throw new InvalidOperationException("The setting 'Scalar:StaffClientId' is missing.");

        app.MapScalarApiReference(options => options
            .AddPreferredSecuritySchemes(StaffSignInDocument.SchemeName)
            .AddAuthorizationCodeFlow(StaffSignInDocument.SchemeName, flow =>
            {
                flow.ClientId = clientId;
                flow.Pkce = Pkce.Sha256;
                flow.SelectedScopes = [StaffSignInDocument.ApiScope(audience)];
            }));

        return app;
    }

    private static (string Authority, string Audience) ReadStaffSettings(IConfiguration configuration)
    {
        var authority = configuration["Authentication:Staff:Authority"]
            ?? throw new InvalidOperationException("The setting 'Authentication:Staff:Authority' is missing.");
        var audience = configuration["Authentication:Staff:Audience"]
            ?? throw new InvalidOperationException("The setting 'Authentication:Staff:Audience' is missing.");

        return (authority, audience);
    }
}
```

`AddPreferredSecuritySchemes` makes the sign-in the one that Scalar shows first. `Pkce.Sha256` makes Scalar send the PKCE challenge, which a public client needs. `SelectedScopes` is the scope that Scalar asks Entra for.
