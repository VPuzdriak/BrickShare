# Lesson 1.1. Repository, solution, global.json, and .gitignore

Previous: none · Next: 1.2 Central build settings: `Directory.Build.props`, nullable, warnings as errors

## Summary

We set up the repository root for the BrickShare solution. At the end, the repo has a `BrickShare.slnx` solution file, a `global.json` that pins the .NET 10 SDK, and a `.gitignore` that keeps build output and local secrets out of Git. No projects exist yet, so there is nothing to build. The next lessons add the shared build settings and the first projects.

## The problem

The repository has a README, the docs, and the Claude skills. It has no solution file, no SDK pin, and no `.gitignore`.

Without these files:

- Each developer can use a different .NET SDK. The same code then builds in one place and fails in another.
- Tools have no solution file to open or build as one unit. The commands in the README (`dotnet build BrickShare.slnx`) do not work yet.
- `bin/` and `obj/` folders, user settings, and local `.env` files can end up in a commit. Secrets in a commit are hard to remove later.

This lesson has no business rule from `docs/features/`. It sets up the repository layout from [Architecture.md section 7](../Architecture.md#7-solution-structure). We pin the SDK because the course targets .NET 10 and the course must build the same way on every machine.

We use the `global.json` file for the SDK pin. It lets the SDK roll forward to newer .NET 10 patch releases. We do not pin one exact patch version, so a student with a newer 10.0 SDK can still build the course.

## Step 1. Check the starting state

This step changes no files. It confirms that the Git tree is clean and that a .NET 10 SDK is installed.

Run from the repository root:

```powershell
git status
dotnet --version
```

Expected: `git status` reports a clean tree on branch `lesson-1.1`. `dotnet --version` prints a `10.0.x` version. If it prints a lower version or an error, install the .NET 10 SDK first, then run the command again.

## Step 2. Pin the SDK with global.json

We pin the SDK at the root of the repository, so every command runs with the same .NET 10 band. `rollForward` set to `latestFeature` allows any newer 10.0 SDK from `10.0.100` upward.

Run from the repository root to generate the file with the .NET SDK template:

```powershell
dotnet new globaljson --sdk-version 10.0.100 --roll-forward latestFeature
```

The command creates `global.json` in the current folder. The file should match the content below. If it differs, replace it with this content.

`global.json`

```json
{
  "sdk": {
    "version": "10.0.100",
    "rollForward": "latestFeature"
  }
}
```

Run:

```powershell
dotnet --version
```

Expected: the command prints a `10.0.x` version. If no SDK from 10.0.100 or newer is installed, the command fails with a message that a compatible SDK was not found. That message means the pin works. Install a 10.0 SDK and run the command again.

## Step 3. Create the solution file

We create the solution at the root and name it `BrickShare`. We use the `slnx` format. It is the XML-based solution format, and it is easier to read in a diff than the old `.sln` format.

The .NET 10.0.100 SDK creates the older `.sln` format by default and does not accept `--format slnx`. So we create the `.sln` with the CLI, convert it with `dotnet sln migrate`, and delete the `.sln`.

Run from the repository root:

```powershell
dotnet new sln --name BrickShare
dotnet sln BrickShare.sln migrate
Remove-Item BrickShare.sln
dotnet sln BrickShare.slnx list
```

The `migrate` command creates `BrickShare.slnx`. The file holds only an empty root element, with no projects.

`BrickShare.slnx`

```xml
<Solution />
```

Expected: `dotnet new sln` prints that the template was created. `migrate` prints that `BrickShare.slnx` was generated. The last command reports that the solution has no projects. The exact wording depends on the SDK version. The first projects arrive in lesson 1.5 (test projects) and lesson 2.1 (Catalog).

## Step 4. Add the .gitignore file

We generate the standard .NET ignore file with the `gitignore` template. It covers build output, IDE files, and the other usual .NET entries. Then we add the few rules that the template does not cover for this course: macOS files and local settings and secrets.

Run from the repository root:

```powershell
dotnet new gitignore
```

The command creates `.gitignore` in the current folder. The file is long, so the script does not show it in full. If `.gitignore` already exists, the command asks before it overwrites the file. Answer no, then add the lines below to the end of the existing file.

Add these lines to the end of `.gitignore`. Skip any line that the template already contains:

`.gitignore`

```gitignore
# macOS and local settings
.DS_Store
.claude/settings.local.json
*.local.json
.env
```

The template ignores `bin/` and `obj/` at any depth, because its patterns have no leading slash. This matches the rule that every `bin` and `obj` folder stays out of Git.

Expected: `.gitignore` exists at the repository root. Git does not track it yet. Step 5 checks the rules.

## Step 5. Check the ignore rules and the new files

No test covers this lesson. There is no business rule to test, so there is no red step. The check is the Git output below. This step does not change any file.

Run from the repository root:

```powershell
git check-ignore -v src/Example/bin/Debug/app.dll
git check-ignore -v src/Example/obj/project.assets.json
git check-ignore -v .claude/settings.local.json
git status --short
```

Expected:

- Each of the first three commands prints one line with the matching rule from `.gitignore`. The first line points at the `[Bb]in/` rule, the second at the `[Oo]bj/` rule, and the third at the `*.local.json` rule.
- `git status --short` lists three new files: `.gitignore`, `BrickShare.slnx`, and `global.json`. It shows no `bin/`, `obj/`, or `.local.json` files.

If a path is not ignored, the first command prints nothing. Check that `.gitignore` is at the repository root and that the pattern is spelled exactly as above.

## Step 6. Commit the setup

Commit the three files on the `lesson-1.1` branch. Commit only these files.

Run:

```powershell
git add .gitignore global.json BrickShare.slnx
git commit -m "Add solution, SDK pin, and .gitignore"
```

Expected: Git reports one commit with three new files. `git status` then shows a clean tree.

- Build output, IDE files, and local settings stay out of Git.
