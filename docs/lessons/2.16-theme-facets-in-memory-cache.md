# Lesson 2.16. Theme facets with in-memory caching

Features: [F02](../features/02-catalog-browsing-and-search.md#endpoints)
Previous: [2.15](2.15-fuzzy-search-pg-trgm.md) · Next: 3.1 Multi-stage Dockerfile: chiseled runtime image, non-root user

## Summary

`GET /catalog/themes` returns every theme with the number of active sets in it. The filter sidebar uses this list. The counts are cached in memory for five minutes, so a busy catalog page does not count sets on every request. At the end the Api tests for theme facets are green, and the browse tests from lesson 2.14 and 2.15 still pass.

## The problem

Customers filter the catalog by theme, but the sidebar has no list of themes yet. The only theme data is in the `themes` table, which the catalog fills when an admin submits a set. [Catalog browsing and search](../features/02-catalog-browsing-and-search.md) sets the rules:

> Facet counts for the filter sidebar (sets per theme, age bands) are cached for a few minutes.

The endpoint table in the same doc names the route:

| Method | Route | Policy | Purpose |
|--------|-------|--------|---------|
| GET | `/catalog/themes` | Anonymous | Themes with set counts (filter sidebar) |

[Browse sets](../features/02-catalog-browsing-and-search.md#rules) also says that only active sets are listed. A count that includes retired sets would not match the list a customer gets after filtering by that theme. So the count uses the same rule.

Concepts this lesson introduces:

- **Facet count.** A facet is a filter with a count next to each value. Here the value is a theme and the count is the number of active sets in it.
- **One query for many counts.** The count is a subquery inside the projection. EF Core turns the whole request into one SQL statement that returns each theme and its count.
- **In-memory cache with a fixed expiry.** `IMemoryCache` is already registered in `Program.cs` through `AddMemoryCache()`. The entry expires five minutes after it is written. A sliding expiry would keep the entry alive while people keep browsing, so the counts would never refresh. An absolute expiry refreshes them on a fixed schedule.
- **A cache lives as long as the host.** Respawn clears the database between tests, but it does not clear the cache. The test factory must clear the cache too. This is the one test concern this lesson adds.

Scope decisions made in this lesson:

- **Active sets only.** The count matches the browse list for that theme.
- **Themes with no active sets stay in the list, with a count of 0.** The sidebar can show them greyed out. The feature doc does not say whether to hide them. This is an open point for the author.
- **One cache entry for all themes.** The endpoint has no parameters, so one key is enough.
- **Five minutes.** The doc says "a few minutes". This lesson picks five.
- **No cache invalidation on set changes.** The doc accepts a stale count for a few minutes, so a new set can take up to five minutes to show in its theme.
- **No age-band facets.** `LegoSet` has no minimum age yet (see lesson 2.14). The age facet comes with that change.

## Step 3. Green: the endpoint counts active sets per theme

The endpoint is a new slice in `Features/Themes/Facets/`. The handler runs one query. The theme list is sorted by name, then by id, so the order is stable.

`src/Services/Catalog/BrickShare.Catalog.Api/Features/Themes/Facets/GetThemeFacets.cs`

```csharp
using System.Collections.Generic;
using System.Linq;
using System.Threading;
using System.Threading.Tasks;

using BrickShare.Catalog.Api.Infrastructure.Persistence;

using Microsoft.AspNetCore.Builder;
using Microsoft.AspNetCore.Http;
using Microsoft.AspNetCore.Http.HttpResults;
using Microsoft.AspNetCore.Routing;
using Microsoft.EntityFrameworkCore;

namespace BrickShare.Catalog.Api.Features.Themes.Facets;

public static class GetThemeFacets
{
    public static void MapGetThemeFacets(this RouteGroupBuilder themes) =>
        themes.MapGet("/", Handle);

    private static async Task<Ok<List<ThemeFacetResponse>>> Handle(
        CatalogDbContext dbContext,
        CancellationToken cancellationToken)
    {
        var facets = await CountActiveSetsAsync(dbContext, cancellationToken);

        return TypedResults.Ok(facets);
    }

    private static Task<List<ThemeFacetResponse>> CountActiveSetsAsync(
        CatalogDbContext dbContext, CancellationToken cancellationToken) =>
        dbContext.Themes
            .OrderBy(theme => theme.Name)
            .ThenBy(theme => theme.Id)
            .Select(theme => new ThemeFacetResponse(
                theme.Id,
                theme.Name,
                dbContext.LegoSets.Count(legoSet => legoSet.IsActive && legoSet.ThemeId == theme.Id)))
            .ToListAsync(cancellationToken);
}
```

The count is a subquery per theme. A theme with no matching set gets 0, because `Count` returns 0 and the theme row is still returned.

The endpoint group is new, so it needs its own file. It declares the policy on the group, as CLAUDE.md requires. The group is anonymous, like the public set endpoints.

## Step 4. Green: cache the counts for five minutes and clear the cache per test

The cache stores the list for five minutes under one key. The handler reads the cache first. On a miss it runs the count query and stores the result. The expiry is absolute, so the entry is removed five minutes after it is written.

Replace the whole file with this content. The query method stays the same. The handler and the two constants are new, and the `using` for `Microsoft.Extensions.Caching.Memory` is added.

`src/Services/Catalog/BrickShare.Catalog.Api/Features/Themes/Facets/GetThemeFacets.cs`

```csharp
using System;
using System.Collections.Generic;
using System.Linq;
using System.Threading;
using System.Threading.Tasks;

using BrickShare.Catalog.Api.Infrastructure.Persistence;

using Microsoft.AspNetCore.Builder;
using Microsoft.AspNetCore.Http;
using Microsoft.AspNetCore.Http.HttpResults;
using Microsoft.AspNetCore.Routing;
using Microsoft.EntityFrameworkCore;
using Microsoft.Extensions.Caching.Memory;

namespace BrickShare.Catalog.Api.Features.Themes.Facets;

public static class GetThemeFacets
{
    private const string CacheKey = "catalog:theme-facets";

    private static readonly TimeSpan CacheDuration = TimeSpan.FromMinutes(5);

    public static void MapGetThemeFacets(this RouteGroupBuilder themes) =>
        themes.MapGet("/", Handle);

    private static async Task<Ok<List<ThemeFacetResponse>>> Handle(
        CatalogDbContext dbContext,
        IMemoryCache cache,
        CancellationToken cancellationToken)
    {
        var facets = await cache.GetOrCreateAsync(CacheKey, entry =>
        {
            entry.AbsoluteExpirationRelativeToNow = CacheDuration;

            return CountActiveSetsAsync(dbContext, cancellationToken);
        });

        return TypedResults.Ok(facets!);
    }

    private static Task<List<ThemeFacetResponse>> CountActiveSetsAsync(
        CatalogDbContext dbContext, CancellationToken cancellationToken) =>
        dbContext.Themes
            .OrderBy(theme => theme.Name)
            .ThenBy(theme => theme.Id)
            .Select(theme => new ThemeFacetResponse(
                theme.Id,
                theme.Name,
                dbContext.LegoSets.Count(legoSet => legoSet.IsActive && legoSet.ThemeId == theme.Id)))
            .ToListAsync(cancellationToken);
}
```

`GetOrCreateAsync` runs the factory only on a miss. A hit returns the stored list and skips the query. `AbsoluteExpirationRelativeToNow` counts from the write, not from the last read. This is why the counts refresh every five minutes even under constant traffic.

The cache is a singleton inside the test host. Respawn does not touch it. Without a reset, a theme facet from one test would appear in the next test. The factory must clear the cache on each reset.

`IMemoryCache` has no clear method. The `MemoryCache` class has `Compact`. Calling `Compact(1.0)` removes every entry. The factory casts the registered `IMemoryCache` to `MemoryCache` for this call.

## Result

What now works:

- `GET /catalog/themes` is anonymous. It returns every theme, sorted by name, with the number of active sets in it. A theme with no active sets has a count of 0.
- The counts come from memory for five minutes after the first request. A new set shows in its theme's count after the cache entry expires.
- Each Api test starts with an empty cache, so tests do not see each other's counts.

Not in this lesson: age-band facets, the expiry test, and cache invalidation when a set changes. See the scope decisions above.
