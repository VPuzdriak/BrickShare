# Lesson 2.8i. Lookup endpoint: `404` and `400` as `ProblemDetails`, admin only, test-first

Features: [F01](../features/01-catalog-management.md#lookup-in-rebrickable)
Previous: [2.8h](2.8h-lookup-set-draft.md) · Next: [2.8j](2.8j-lookup-unavailable-503.md)

## Summary

The lookup answers `404` when Rebrickable does not know the set, and `400` when the text is not a set number. Both answers are `ProblemDetails`. A non-admin is refused. At the end all four lookup tests are green.

## The problem

[Catalog management](../features/01-catalog-management.md#lookup-in-rebrickable) says: "A set number unknown to Rebrickable returns `404`." The feature doc does not say what an invalid number returns. This lesson uses `400`, as lesson 2.6b does for invalid input. The rule for `ProblemDetails` is in [Architecture.md section 7.1](../Architecture.md#71-domain-driven-design): business errors return results, and handlers map them to `ProblemDetails`.

## Step 2. Red: an unknown set number returns `404`

The fake does not know `99999`, so it returns `null`. The handler from lesson 2.8h dereferences that `null`, so the request fails with `500`.

`tests/Services/Catalog/BrickShare.Catalog.Api.Tests/LookupSetTests.cs` (add this test after `Admin_gets_the_set_draft_for_a_set_number_without_a_variant`)

```csharp
    [Fact]
    public async Task Lookup_returns_404_problem_details_when_rebrickable_does_not_know_the_set()
    {
        using var client = Factory.CreateClient();

        using var response = await client.SendWithTokenAsync(
            HttpMethod.Get, "/catalog/sets/lookup/99999", TestTokens.Create("Admin"));

        response.StatusCode.Should().Be(HttpStatusCode.NotFound);
        response.Content.Headers.ContentType!.MediaType.Should().Be("application/problem+json");
    }
```

Expected: red. `Lookup_returns_404_problem_details_when_rebrickable_does_not_know_the_set` fails with "Expected ... to be HttpStatusCode.NotFound, but found HttpStatusCode.InternalServerError".

## Step 3. Green: answer `404` for an unknown set

`src/Services/Catalog/BrickShare.Catalog.Api/Features/Sets/SetProblems.cs` (add this method after `NotFound`)

```csharp
    public static ProblemHttpResult UnknownSetNumber(string setNumber) =>
        TypedResults.Problem(
            title: "Set not found",
            detail: $"Rebrickable has no set with number {setNumber}.",
            statusCode: StatusCodes.Status404NotFound);
```

`src/Services/Catalog/BrickShare.Catalog.Api/Features/Sets/Lookup/LookupSet.cs` (replace the `Handle` method)

Before:

```csharp
    private static async Task<Ok<SetDraftResponse>> Handle(
        string setNumber, ISetSpecificationProvider specifications, CancellationToken cancellationToken)
    {
        var specification = await specifications.FindAsync(
            RebrickableSetNumber.Parse(setNumber).Value, cancellationToken);

        return TypedResults.Ok(SetDraftResponse.From(specification!));
    }
```

After:

```csharp
    private static async Task<Results<Ok<SetDraftResponse>, ProblemHttpResult>> Handle(
        string setNumber, ISetSpecificationProvider specifications, CancellationToken cancellationToken)
    {
        var specification = await specifications.FindAsync(
            RebrickableSetNumber.Parse(setNumber).Value, cancellationToken);

        if (specification is null)
        {
            return SetProblems.UnknownSetNumber(setNumber);
        }

        return TypedResults.Ok(SetDraftResponse.From(specification));
    }
```

## Step 5. Green: refuse an invalid set number with `400`

`src/Services/Catalog/BrickShare.Catalog.Api/Features/Sets/SetProblems.cs` (add this method after `UnknownSetNumber`)

```csharp
    public static ProblemHttpResult InvalidSetNumber(string setNumber) =>
        TypedResults.Problem(
            title: "Invalid set number",
            detail: $"'{setNumber}' is not a set number. Use digits, optionally followed by a dash and a variant number, for example 10294 or 10294-2.",
            statusCode: StatusCodes.Status400BadRequest);
```

`src/Services/Catalog/BrickShare.Catalog.Api/Features/Sets/Lookup/LookupSet.cs` (replace the `Handle` method)

Before:

```csharp
    private static async Task<Results<Ok<SetDraftResponse>, ProblemHttpResult>> Handle(
        string setNumber, ISetSpecificationProvider specifications, CancellationToken cancellationToken)
    {
        var specification = await specifications.FindAsync(
            RebrickableSetNumber.Parse(setNumber).Value, cancellationToken);

        if (specification is null)
        {
            return SetProblems.UnknownSetNumber(setNumber);
        }

        return TypedResults.Ok(SetDraftResponse.From(specification));
    }
```

After:

```csharp
    private static async Task<Results<Ok<SetDraftResponse>, ProblemHttpResult>> Handle(
        string setNumber, ISetSpecificationProvider specifications, CancellationToken cancellationToken)
    {
        var parsed = RebrickableSetNumber.Parse(setNumber);

        if (parsed.IsFailure)
        {
            return SetProblems.InvalidSetNumber(setNumber);
        }

        var specification = await specifications.FindAsync(parsed.Value, cancellationToken);

        if (specification is null)
        {
            return SetProblems.UnknownSetNumber(setNumber);
        }

        return TypedResults.Ok(SetDraftResponse.From(specification));
    }
```

## Step 6. Guard: a non-admin is refused

The route sits in the `/catalog/sets` group, which already requires `AdminOnly`. This test passes at once. It is a guard: a later change that moves the route out of the group fails it.

`tests/Services/Catalog/BrickShare.Catalog.Api.Tests/LookupSetTests.cs` (add this test after `Lookup_returns_400_problem_details_for_an_invalid_set_number`)
