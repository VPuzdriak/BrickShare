# Lesson 2.7. Themes and theme mapping

Features: [F01](../features/01-catalog-management.md)
Previous: [2.6e](2.6e-test-isolation-with-respawn.md) · Next: 2.8a Rebrickable set number: default `-1` variant and explicit variants, test-first

## Summary

We add the `Theme` aggregate and a mapping from a Rebrickable theme to its top-level theme. A Rebrickable theme can be nested, for example "Star Wars" with the sub-theme "Episode I". The catalog keeps only the top-level theme, so sub-themes are not stored. Every rule is written test-first in the Domain project. At the end four new domain tests pass. No endpoint, table, or migration changes, because nothing calls the mapping yet.

## The problem

[Catalog management](../features/01-catalog-management.md#lookup-in-rebrickable) says how a set gets its theme:

> Catalog maps it to a local theme by Rebrickable theme id. The top-level parent theme becomes the catalog theme, and the sub-theme is stored in attributes. A missing local theme is created on submit.

This lesson implements the rule for the catalog theme. It does not keep sub-themes. The sub-theme part of the quote is not used, so we do not store it in attributes.

Before this lesson the domain has no theme at all. That causes two problems:

- A set has no theme to point to. [Architecture.md section 3.2](../Architecture.md#32-catalog-service) lists `Theme` as its own model with its own id (`Theme.Id`, a UUID v7 generated by Catalog). Other parts of the service refer to a theme by that id, not by the Rebrickable id.
- Rebrickable themes can be nested. If the catalog used the theme as Rebrickable returns it, a set could get a sub-theme as its theme, and browsing by theme (lessons 2.14 and 2.16) would see many small themes instead of a short list. The mapping makes every set point to a top-level theme.

The concepts we introduce:

- **Theme aggregate.** `Theme` inherits `AggregateRoot<Guid>` like `LegoSet`. It gets its id from the caller, so the domain reads no clock and creates no ids. Its name and its Rebrickable id come from the top-level Rebrickable theme.
- **Plain data for the external tree.** `RebrickableTheme` is a record with an id, a name, and an optional parent. It holds data only. The name says where the data comes from. The domain never calls Rebrickable. The adapter in lesson 2.8 reads the theme records, follows the parent ids, and builds the tree. The mapping then works on plain records, so its tests need no HTTP and no stub.
- **Mapping as a property.** `TopLevel` walks up the parent chain and returns the top-level theme. It has no state and no side effects.

What this lesson does not do:

- It does not store themes. The `themes` table, the `LegoSet.ThemeId` column, and the migration come in lesson 2.9, when a set is submitted.
- It does not look up themes. The rule "a missing local theme is created on submit" is implemented by the handler in lesson 2.9. This lesson gives the handler the factory `Theme.FromRebrickable`.

```csharp
using System;

using BrickShare.SharedKernel;

namespace BrickShare.Catalog.Domain;

public sealed class Theme : AggregateRoot<Guid>
{
    private Theme(Guid id, string name, int rebrickableThemeId)
        : base(id)
    {
        Name = name;
        RebrickableThemeId = rebrickableThemeId;
    }

    public string Name { get; }

    public int RebrickableThemeId { get; }

    public static Theme FromRebrickable(Guid id, RebrickableTheme topLevelTheme) =>
        new(id, topLevelTheme.Name, topLevelTheme.Id);
}
```

## Step 9. Green: check that the theme is top-level

The factory checks the parent first and throws `ArgumentException` for a sub-theme. The check runs before the theme is created, so an invalid theme never exists.

`src/Services/Catalog/BrickShare.Catalog.Domain/Theme.cs` (replace the factory method with this one)

Before:

```csharp
    public static Theme FromRebrickable(Guid id, RebrickableTheme topLevelTheme) =>
        new(id, topLevelTheme.Name, topLevelTheme.Id);
```

After:

```csharp
    public static Theme FromRebrickable(Guid id, RebrickableTheme topLevelTheme)
    {
        if (topLevelTheme.Parent is not null)
        {
            throw new ArgumentException("Only a top-level Rebrickable theme becomes a catalog theme.", nameof(topLevelTheme));
        }

        return new Theme(id, topLevelTheme.Name, topLevelTheme.Id);
    }
```
