# Lesson 1.7. `Money` value object, test-first

Previous: [1.6](1.6-shared-kernel.md) · Next: 1.8 `BrickShare.TestKit`: builders, `FakeTimeProvider`, test tokens

## Summary

We add the `Money` value object to `BrickShare.SharedKernel`. It holds an amount in minor units (a `long`) and a currency code. The course uses one currency, EUR, so `Money` accepts only EUR. We write each rule test-first. At the end `Money` rejects a negative amount and any currency other than EUR, and fourteen tests pass.

## The problem

The shared kernel has entities, aggregates, and results, but no type for money. Prices, deposits, rental amounts, and payments all carry money. Without a shared type, each service picks its own representation, and the choices drift:

- **Precision.** A `decimal` or `double` can round differently in two places. [CLAUDE.md](../../CLAUDE.md) forbids both for stored amounts. We store money as `long` minor units, so EUR 12.50 is `1250`.
- **Currency.** An amount without its currency can be added to an amount in another currency by mistake. The amount and the currency code must travel together. [Architecture.md section 1.3](../Architecture.md#13-scope-and-assumptions) fixes the course to one currency, EUR, so `Money` accepts only EUR.
- **Sign.** An amount cannot be negative. [Architecture.md section 7.1](../Architecture.md#71-domain-driven-design) models a refund as a payment kind (`Refund`), so an amount is a size and the kind gives the direction.

Money appears in many places. For example, a reservation copies the catalog prices at booking time: "Prices, deposit, replacement value, late fee and minimum days are copied from the catalog at booking time" ([06-reservation-and-payment.md](../features/06-reservation-and-payment.md)). Each copy must keep the same rules, so the rules belong in one type.

The concept is a **value object**. It has no identity. Two `Money` values are equal when their amount and currency are equal. It is immutable, and it validates in its constructor, as [Architecture.md section 7.1](../Architecture.md#71-domain-driven-design) requires. A C# `record` gives value equality for free, so we use one.

We add no arithmetic in this lesson. Later lessons add the operations they need, such as the rental amount in [lesson 6.2](../CoursePlan.md).

## Step 3. Green: the `Money` record

We add the simplest `Money` that compiles. It sets the two properties and does no validation yet. Its constructor takes the amount and the currency. We write the class with an explicit constructor from the start, because a positional record cannot validate its arguments. The validation comes in steps 5 and 7.

We create the file with the CLI. Run from the repository root:

```powershell
dotnet new record -n Money -o src/BuildingBlocks/BrickShare.SharedKernel
```

`src/BuildingBlocks/BrickShare.SharedKernel/Money.cs` (replace the template record with this content)

Before: the template's empty `Money` record.

After:

```csharp
namespace BrickShare.SharedKernel;

public sealed record Money
{
    public Money(long amount, string currency)
    {
        Amount = amount;
        Currency = currency;
    }

    public long Amount { get; }

    public string Currency { get; }
}
```

The `record` keyword gives value equality. The properties have no setters, so a `Money` never changes after it is created.

Run from the repository root:

```powershell
dotnet test --project tests/BuildingBlocks/BrickShare.SharedKernel.Tests
```

Expected: green. The run reports ten passed tests: the nine from lesson 1.6 and the new one.

## Step 4. Red: a negative amount is rejected

A negative amount is not a valid price, deposit, or payment amount. We add a test that the constructor throws. The test uses a `Func` so that AwesomeAssertions can catch the exception. The test follows the same style as the `ResultTests` class from lesson 1.6.

`tests/BuildingBlocks/BrickShare.SharedKernel.Tests/MoneyTests.cs` (add the test method after `Money_keeps_the_amount_and_the_currency`)

```csharp

    public void Money_rejects_a_negative_amount()
    {
        Func<Money> create = () => new Money(-1, "EUR");

        create.Should().Throw<ArgumentOutOfRangeException>();
    }
```

Run from the repository root:

```powershell
dotnet test --project tests/BuildingBlocks/BrickShare.SharedKernel.Tests
```

Expected: red. `Money_rejects_a_negative_amount` fails. The assertion reports that no exception was thrown. The other ten tests pass.

## Step 7. Green: accept only EUR

We check the currency code in the constructor, after the amount check. The comparison is ordinal and case-sensitive, so `eur` fails too. The check needs no extra `using` line.

`src/BuildingBlocks/BrickShare.SharedKernel/Money.cs` (add the check after the amount check, before `Amount = amount;`)

Before:

```csharp
        ArgumentOutOfRangeException.ThrowIfNegative(amount);

        Amount = amount;
```

After:

```csharp
        ArgumentOutOfRangeException.ThrowIfNegative(amount);

        if (currency != "EUR")
        {
            throw new ArgumentException("Only EUR is supported.", nameof(currency));
        }

        Amount = amount;
```

The message and the parameter name go into the exception, so the caller sees which argument is wrong.

```powershell

```

Expected: green. The run reports fourteen passed tests. The theory counts as three tests.

## Step 8. Check the final file

This step changes no code. The class has two rules, the amount and the currency, and each rule has a test. The constructor is short, so no refactor is needed.

`src/BuildingBlocks/BrickShare.SharedKernel/Money.cs` now reads:

```csharp
using System;

namespace BrickShare.SharedKernel;

public sealed record Money
{
    public Money(long amount, string currency)
    {
        ArgumentOutOfRangeException.ThrowIfNegative(amount);

        if (currency != "EUR")
        {
            throw new ArgumentException("Only EUR is supported.", nameof(currency));
        }

        Amount = amount;
        Currency = currency;
    }

    public long Amount { get; }

    public string Currency { get; }
}
```

```powershell

```
