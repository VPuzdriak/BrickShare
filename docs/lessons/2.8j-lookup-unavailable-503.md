## The problem

[Catalog management](../features/01-catalog-management.md#lookup-in-rebrickable) now says: "If Rebrickable is down, slow, or still failing after the retries, the lookup returns `503` with `ProblemDetails`." The adapter throws `SetSpecificationUnavailableException` for that case, from lesson 2.8f. Without a handler, the exception becomes `500`. The handler catches the domain exception and answers `503`.

## Step 2. Red: Rebrickable unavailable returns `503`

The fake gets a switch. When it is on, the fake throws the domain exception, the same as the adapter does on a failure. The handler does not catch it yet, so the response is `500`.

`tests/Services/Catalog/BrickShare.Catalog.Api.Tests/FakeSetSpecificationProvider.cs` (add this property after `_specifications`, and replace `FindAsync`)

Add this property:

```csharp
    public bool IsUnavailable { get; set; }
```

Replace `FindAsync` with:

```csharp
    public Task<SetSpecification?> FindAsync(RebrickableSetNumber setNumber, CancellationToken cancellationToken)
    {
        if (IsUnavailable)
        {
            throw new SetSpecificationUnavailableException("Rebrickable is unavailable.");
        }

        return Task.FromResult(_specifications.GetValueOrDefault(setNumber.Value));
    }
```

`tests/Services/Catalog/BrickShare.Catalog.Api.Tests/LookupSetTests.cs` (add this test after `Employee_is_forbidden_to_look_up_a_set`)

```csharp
    [Fact]
    public async Task Lookup_returns_503_problem_details_when_rebrickable_is_unavailable()
    {
        Factory.SetSpecifications.IsUnavailable = true;

        try
        {
            using var client = Factory.CreateClient();

            using var response = await client.SendWithTokenAsync(
                HttpMethod.Get, "/catalog/sets/lookup/10294", TestTokens.Create("Admin"));

            response.StatusCode.Should().Be(HttpStatusCode.ServiceUnavailable);
            response.Content.Headers.ContentType!.MediaType.Should().Be("application/problem+json");
        }
        finally
        {
            Factory.SetSpecifications.IsUnavailable = false;
        }
    }
```

The `finally` block resets the switch, so the other tests in the class are not affected.

## Step 3. Green: answer `503` when Rebrickable is unavailable

`src/Services/Catalog/BrickShare.Catalog.Api/Features/Sets/Lookup/LookupSet.cs` (replace the `Handle` method)

Before:

```csharp
    private static async Task<Results<Ok<SetDraftResponse>, ProblemHttpResult>> Handle(
        string setNumber, ISetSpecificationProvider specifications, CancellationToken cancellationToken)
    {
        var parsed = RebrickableSetNumber.Parse(setNumber);

        if (parsed.IsFailure)
        {
            return SetProblems.InvalidSetNumber(setNumber);
        }

        var specification = await specifications.FindAsync(parsed.Value, cancellationToken);

        if (specification is null)
        {
            return SetProblems.UnknownSetNumber(setNumber);
        }

        return TypedResults.Ok(SetDraftResponse.From(specification));
    }
```

After:

```csharp
    private static async Task<Results<Ok<SetDraftResponse>, ProblemHttpResult>> Handle(
        string setNumber, ISetSpecificationProvider specifications, CancellationToken cancellationToken)
    {
        var parsed = RebrickableSetNumber.Parse(setNumber);

        if (parsed.IsFailure)
        {
            return SetProblems.InvalidSetNumber(setNumber);
        }

        SetSpecification? specification;

        try
        {
            specification = await specifications.FindAsync(parsed.Value, cancellationToken);
        }
        catch (SetSpecificationUnavailableException)
        {
            return SetProblems.RebrickableUnavailable();
        }

        if (specification is null)
        {
            return SetProblems.UnknownSetNumber(setNumber);
        }

        return TypedResults.Ok(SetDraftResponse.From(specification));
    }
```
