# Lesson 2.6a. Create a set: name and active flag, persistence, `POST /catalog/sets`

Features: [F01](../features/01-catalog-management.md)
Previous: [2.5](2.5-authorization-and-dev-tokens.md) · Next: [2.6b](2.6b-validation-with-fluentvalidation.md) Validation with FluentValidation and `ProblemDetails` for create

## Summary

We give `LegoSet` a name and an active flag, map both to the database with a migration, and add `POST /catalog/sets`. An admin can create a set and gets `201` with a location. An employee gets `403`. The request is not validated yet: lesson 2.6b adds the rules. At the end the create tests are green.

## The problem

The Catalog Service has a `LegoSet` aggregate with a number, prices, and minimum rental days, but no name and no way to tell an active set from a deactivated one. No endpoint creates a set. [Catalog management](../features/01-catalog-management.md#sets) says:

- "A set has: LEGO set number ..., name, ..." so a set needs a name.
- "Deleting a set is a soft delete (deactivate)." So a set needs a flag that says whether it is active. Lesson 2.6d uses the flag.
- "Catalog gives every set and instance its own id." The id comes from the Catalog Service, so the handler creates it with `Guid.CreateVersion7()`.

The lesson adds the create path only. Validation, `ProblemDetails`, update, and deactivate come in the next lessons. The request is passed to the aggregate as it is, so a bad value (for example a set number with a suffix) reaches the value object and fails there. Lesson 2.6b closes that gap.

Currency is fixed to EUR, as in [Architecture.md section 1](../Architecture.md#1-overview), so the request has no currency field.

        LateFeePerDay = lateFeePerDay;
        IsActive = true;

    public string Name { get; private set; }

    public MinRentalDays MinRentalDays { get; private set; }

    public Money DailyPrice { get; private set; }

    public Money Deposit { get; private set; }

## Step 5. Red: integration tests for `POST /catalog/sets`

The endpoint tests run against the real host, with a PostgreSQL container and the test tokens from lesson 2.5. Two tests describe the create path in this lesson. An admin creates a set and gets `201` with a location. An employee is refused with `403`, because `AdminOnly` covers the whole group.

The tests share one helper that builds a valid body and sends a request with a token. The helper comes first, so the test file compiles on its own.

`tests/Services/Catalog/BrickShare.Catalog.Api.Tests/SetRequests.cs` (new file)

```csharp
using System.Net.Http;
using System.Net.Http.Headers;
using System.Net.Http.Json;
using System.Threading.Tasks;

using Xunit;

namespace BrickShare.Catalog.Api.Tests;

public static class SetRequests
{
    public static object ValidBody(string legoSetNumber = "10294", string name = "Millennium Falcon") => new
    {
        legoSetNumber,
        name,
        minRentalDays = 3,
        dailyPrice = 1500,
        deposit = 15000,
        replacementValue = 30000,
        lateFeePerDay = 500
    };

    public static async Task<HttpResponseMessage> SendWithTokenAsync(
        this HttpClient client, HttpMethod method, string path, string token, object? body = null)
    {
        using var request = new HttpRequestMessage(method, path);
        request.Headers.Authorization = new AuthenticationHeaderValue("Bearer", token);

        if (body is not null)
        {
            request.Content = JsonContent.Create(body);
        }

        return await client.SendAsync(request, TestContext.Current.CancellationToken);
    }
}
```

The contract file holds the request and the response. The request is a plain record with primitive fields. It has no rules yet; lesson 2.6b adds them. The response shows the id, the number, the name, and the active flag.

`src/Services/Catalog/BrickShare.Catalog.Api/Features/Sets/SetContracts.cs` (new file)

```csharp
using System;

using BrickShare.Catalog.Domain;

namespace BrickShare.Catalog.Api.Features.Sets;

public sealed record SetRequest(
    string LegoSetNumber,
    string Name,
    int MinRentalDays,
    long DailyPrice,
    long Deposit,
    long ReplacementValue,
    long LateFeePerDay);

public sealed record SetResponse(Guid Id, string LegoSetNumber, string Name, bool IsActive)
{
    public static SetResponse From(LegoSet legoSet) =>
        new(legoSet.Id, legoSet.LegoSetNumber.Value, legoSet.Name, legoSet.IsActive);
}
```

The mapping goes in an extension method, in its own file, so the request stays a plain record. `ToLegoSet` turns the primitive fields into value objects. It uses the shop currency, EUR.

`src/Services/Catalog/BrickShare.Catalog.Api/Features/Sets/SetMappings.cs` (new file)

```csharp
using System;

using BrickShare.Catalog.Domain;
using BrickShare.SharedKernel;

namespace BrickShare.Catalog.Api.Features.Sets;

public static class SetMappings
{
    private const string Currency = "EUR";

    public static LegoSet ToLegoSet(this SetRequest request, Guid id) => new(
        id,
        new LegoSetNumber(request.LegoSetNumber),
        request.Name,
        new MinRentalDays(request.MinRentalDays),
        Price(request.DailyPrice),
        Price(request.Deposit),
        Price(request.ReplacementValue),
        Price(request.LateFeePerDay));

    private static Money Price(long amount) => new(amount, Currency);
}
```

The create slice holds the endpoint and its handler. The handler builds the aggregate, saves it, and returns `201` with a location.

`src/Services/Catalog/BrickShare.Catalog.Api/Features/Sets/Create/CreateSet.cs` (new file)

```csharp
using System;
using System.Threading;
using System.Threading.Tasks;

using BrickShare.Catalog.Api.Infrastructure.Persistence;

using Microsoft.AspNetCore.Builder;
using Microsoft.AspNetCore.Http;
using Microsoft.AspNetCore.Http.HttpResults;
using Microsoft.AspNetCore.Routing;

namespace BrickShare.Catalog.Api.Features.Sets.Create;

public static class CreateSet
{
    public static void MapCreateSet(this RouteGroupBuilder sets) =>
        sets.MapPost("/", Handle);

    private static async Task<Created<SetResponse>> Handle(
        SetRequest request, CatalogDbContext dbContext, CancellationToken cancellationToken)
    {
        var legoSet = request.ToLegoSet(Guid.CreateVersion7());

        dbContext.LegoSets.Add(legoSet);
        await dbContext.SaveChangesAsync(cancellationToken);

        return TypedResults.Created($"/catalog/sets/{legoSet.Id}", SetResponse.From(legoSet));
    }
}
```

The group file states the policy once for every set route. The probe routes from lesson 2.5 stay in place for now.
