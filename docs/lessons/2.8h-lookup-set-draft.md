# Lesson 2.8h. Lookup endpoint: set draft for an admin, fake port in tests

Features: [F01](../features/01-catalog-management.md#lookup-in-rebrickable)
Previous: [2.8g](2.8g-wire-adapter-and-api-key.md) · Next: [2.8i](2.8i-lookup-not-found-and-invalid.md)

## Summary

We add `GET /catalog/sets/lookup/{setNumber}`. An admin gets a set draft for a set number. Nothing is saved. The endpoint tests use a fake port, so they never call Rebrickable. At the end one endpoint test is green.

## The problem

[Catalog management](../features/01-catalog-management.md#lookup-in-rebrickable) says: "Catalog calls the Rebrickable API and returns a set draft. Nothing is saved yet." The draft holds the LEGO set number, the Rebrickable reference, the name, the year, the piece count, the minifigure count, the top-level theme, the image URL, and the page URL. The route belongs to the `/catalog/sets` group, so it inherits the `AdminOnly` policy from lesson 2.5.

using System.Collections.Generic;
using System.Threading;
using System.Threading.Tasks;

using BrickShare.Catalog.Domain;

namespace BrickShare.Catalog.Api.Tests;

public sealed class FakeSetSpecificationProvider : ISetSpecificationProvider

    private readonly Dictionary<string, SetSpecification> _specifications = [];

## Step 3. Red: an admin gets a set draft

The test reads the JSON as `JsonElement`, so no response type is needed yet. The route does not exist, so the call returns `404`.

`tests/Services/Catalog/BrickShare.Catalog.Api.Tests/LookupSetTests.cs` (replace the template class with this content)

```csharp
using System.Net;
using System.Net.Http;
using System.Net.Http.Json;
using System.Text.Json;
using System.Threading.Tasks;

using AwesomeAssertions;

using Xunit;

namespace BrickShare.Catalog.Api.Tests;

[Collection(CatalogCollectionDefinition.Name)]
public class LookupSetTests(CatalogApiFactory factory) : CatalogDatabaseTests(factory)
{
    [Fact]
    public async Task Admin_gets_the_set_draft_for_a_set_number_without_a_variant()
    {
        Factory.SetSpecifications.Add(SetSpecificationData.Titanic());
        using var client = Factory.CreateClient();

        using var response = await client.SendWithTokenAsync(
            HttpMethod.Get, "/catalog/sets/lookup/10294", TestTokens.Create("Admin"));

        response.StatusCode.Should().Be(HttpStatusCode.OK);

        var draft = await response.Content.ReadFromJsonAsync<JsonElement>(TestContext.Current.CancellationToken);
        draft.GetProperty("legoSetNumber").GetString().Should().Be("10294");
        draft.GetProperty("rebrickableSetNumber").GetString().Should().Be("10294-1");
        draft.GetProperty("name").GetString().Should().Be("Titanic");
        draft.GetProperty("pieceCount").GetInt32().Should().Be(9092);
        draft.GetProperty("minifigureCount").GetInt32().Should().Be(3);
        draft.GetProperty("rebrickableThemeId").GetInt32().Should().Be(158);
        draft.GetProperty("themeName").GetString().Should().Be("Top Theme");
    }
}
```

The theme check expects the top-level theme (`158`, `Top Theme`), not the set's sub-theme (`1008`, `Sub Theme`).

Run from the repository root:

```powershell
dotnet test --project tests/Services/Catalog/BrickShare.Catalog.Api.Tests --filter-class "*LookupSetTests"
```

Expected: red. `Admin_gets_the_set_draft_for_a_set_number_without_a_variant` fails with "Expected ... to be HttpStatusCode.OK, but found HttpStatusCode.NotFound".

## Step 4. Green: the lookup slice and the endpoint

The slice is one file: the endpoint, the handler, and the response record. The handler handles only the success path. Lessons 2.8i and 2.8j add the failure paths.

We create the slice file with the CLI. Run from the repository root:

```powershell
dotnet new class -n LookupSet -o src/Services/Catalog/BrickShare.Catalog.Api/Features/Sets/Lookup
```

`src/Services/Catalog/BrickShare.Catalog.Api/Features/Sets/Lookup/LookupSet.cs` (replace the template class with this content)

```csharp
using System;
using System.Threading;
using System.Threading.Tasks;

using BrickShare.Catalog.Domain;

using Microsoft.AspNetCore.Builder;
using Microsoft.AspNetCore.Http;
using Microsoft.AspNetCore.Http.HttpResults;
using Microsoft.AspNetCore.Routing;

namespace BrickShare.Catalog.Api.Features.Sets.Lookup;

public static class LookupSet
{
    public static void MapLookupSet(this RouteGroupBuilder sets) =>
        sets.MapGet("/lookup/{setNumber}", Handle);

    private static async Task<Ok<SetDraftResponse>> Handle(
        string setNumber, ISetSpecificationProvider specifications, CancellationToken cancellationToken)
    {
        var specification = await specifications.FindAsync(
            RebrickableSetNumber.Parse(setNumber).Value, cancellationToken);

        return TypedResults.Ok(SetDraftResponse.From(specification!));
    }
}

public sealed record SetDraftResponse(
    string LegoSetNumber,
    string RebrickableSetNumber,
    string Name,
    int? Year,
    int PieceCount,
    int MinifigureCount,
    int RebrickableThemeId,
    string ThemeName,
    Uri? ImageUrl,
    Uri PageUrl)
{
    public static SetDraftResponse From(SetSpecification specification) => new(
        specification.RebrickableSetNumber.LegoSetNumber.Value,
        specification.RebrickableSetNumber.Value,
        specification.Name,
        specification.Year,
        specification.PieceCount,
        specification.MinifigureCount,
        specification.Theme.TopLevel.Id,
        specification.Theme.TopLevel.Name,
        specification.ImageUrl,
        specification.PageUrl);
}
```

The response shows the top-level theme. The feature doc says: "The top-level parent theme becomes the catalog theme." `TopLevel` from lesson 2.7 gives that theme.
