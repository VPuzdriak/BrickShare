# Lesson 2.6e. Test isolation: Respawn resets, one shared PostgreSQL container for the Catalog tests

Previous: [2.6d](2.6d-deactivate-a-set.md) · Next: 2.7 Themes and theme mapping

## Summary

We reset the database before each Catalog test with Respawn. Each test starts with an empty catalog, so no test depends on the rows of another. Then all Catalog test classes share one collection and one PostgreSQL container, instead of starting one container per class. At the end the whole Catalog suite runs on one container, and the set tests run unchanged.

## The problem

The set tests save rows, and some tests count them. Two problems follow:

- **Leaking rows.** A test that saves a set leaves that row in the database. A later test in the same class sees it. A count, or a test that expects an empty table, then passes or fails depending on the order.
- **Container per class.** Each test class starts its own factory and PostgreSQL container. The six Catalog test classes start six containers. That is slow, and it grows with each Catalog lesson.

The fix has two parts. Respawn deletes the rows before each test, so every test starts from the same empty schema. A collection shares one factory and one container. Respawn keeps the data of the classes apart, so one container is enough.

[Architecture.md section 7.2](../Architecture.md#72-testing-strategy-and-tdd) assigns these checks to integration tests with `WebApplicationFactory` and Testcontainers. No feature rule in `docs/features/` drives this lesson. It is test infrastructure.

The concepts we introduce:

- **Respawn.** A library that deletes the rows of the tables in a schema. It keeps the schema and the tables. It reads the schema once, then each reset is fast.
- **Test base class.** `CatalogDatabaseTests` calls the reset from `InitializeAsync`. xUnit creates a new test class instance for every test, so the reset runs before each one.
- **Collection fixture.** A `CollectionDefinition` with an `ICollectionFixture` shares one fixture among test classes. xUnit runs the classes of one collection one after another, so the resets never overlap.

## Step 2. Reset the database with Respawn before each test

Respawn deletes the rows of the tables in the `public` schema, and it keeps the schema. The package comes from the CLI. The CLI adds the version to `Directory.Packages.props`, and the test project gets no `Version`.

Run from the repository root:

```powershell
dotnet add tests/Services/Catalog/BrickShare.Catalog.Api.Tests package Respawn
```

The factory creates the respawner once, after the migrations run. `SchemasToInclude` limits the reset to the `public` schema. `TablesToIgnore` names the `__EFMigrationsHistory` table, so the reset keeps the migration history. Without it, the reset would also delete the migration rows. `ResetDatabaseAsync` opens a connection and runs the reset. The rest of the factory is the same as in lesson 2.6d.

`tests/Services/Catalog/BrickShare.Catalog.Api.Tests/CatalogApiFactory.cs` (replace the file with this content)

```csharp
using System.Threading.Tasks;

using BrickShare.Catalog.Api.Infrastructure.Persistence;

using Microsoft.AspNetCore.Authentication.JwtBearer;
using Microsoft.AspNetCore.Hosting;
using Microsoft.AspNetCore.Mvc.Testing;
using Microsoft.AspNetCore.TestHost;
using Microsoft.EntityFrameworkCore;
using Microsoft.Extensions.DependencyInjection;
using Microsoft.Extensions.Hosting;

using Npgsql;

using Respawn;

using Testcontainers.PostgreSql;

using Xunit;

namespace BrickShare.Catalog.Api.Tests;

public sealed class CatalogApiFactory : WebApplicationFactory<CatalogApi>, IAsyncLifetime
{
    private readonly PostgreSqlContainer _postgres = new PostgreSqlBuilder("postgres:18").Build();
    private Respawner _respawner = null!;

    public async ValueTask InitializeAsync()
    {
        await _postgres.StartAsync();

        await using var scope = Services.CreateAsyncScope();
        var dbContext = scope.ServiceProvider.GetRequiredService<CatalogDbContext>();
        await dbContext.Database.MigrateAsync();

        await using var connection = new NpgsqlConnection(_postgres.GetConnectionString());
        await connection.OpenAsync();

        _respawner = await Respawner.CreateAsync(connection, new RespawnerOptions
        {
            DbAdapter = DbAdapter.Postgres,
            SchemasToInclude = ["public"],
            TablesToIgnore = ["__EFMigrationsHistory"]
        });
    }

    public async Task ResetDatabaseAsync()
    {
        await using var connection = new NpgsqlConnection(_postgres.GetConnectionString());
        await connection.OpenAsync();

        await _respawner.ResetAsync(connection);
    }

    public override async ValueTask DisposeAsync()
    {
        await base.DisposeAsync();
        await _postgres.DisposeAsync();
    }

    protected override void ConfigureWebHost(IWebHostBuilder builder)
    {
        builder.UseEnvironment(Environments.Development);
        builder.UseSetting("ConnectionStrings:catalog", _postgres.GetConnectionString());
        builder.UseSetting("Authentication:UseDevelopmentIssuer", "true");

        builder.ConfigureTestServices(services =>
            services.PostConfigure<JwtBearerOptions>(JwtBearerDefaults.AuthenticationScheme, options =>
            {
                options.TokenValidationParameters.ValidIssuer = TestTokens.Issuer;
                options.TokenValidationParameters.ValidAudience = TestTokens.Audience;
                options.TokenValidationParameters.IssuerSigningKey = TestTokens.SigningKey;
            }));
    }
}
```

The base class resets the database before each test. xUnit creates a new test class instance for every test, so `InitializeAsync` runs before each one. The class is new, so the CLI creates the file first.

`tests/Services/Catalog/BrickShare.Catalog.Api.Tests/CatalogDatabaseTests.cs` (replace the template file with this content)

```csharp
using System;
using System.Threading.Tasks;

using Xunit;

namespace BrickShare.Catalog.Api.Tests;

public abstract class CatalogDatabaseTests(CatalogApiFactory factory) : IClassFixture<CatalogApiFactory>, IAsyncLifetime
{
    protected CatalogApiFactory Factory { get; } = factory;

    public async ValueTask InitializeAsync() => await Factory.ResetDatabaseAsync();

    public ValueTask DisposeAsync()
    {
        GC.SuppressFinalize(this);

        return ValueTask.CompletedTask;
    }
}
```

The test classes derive from the base class instead of declaring `IClassFixture<CatalogApiFactory>` themselves. The base class declares the fixture for now. Step 3 moves it to a collection.

The base class exposes the factory as the `Factory` property. A test class only passes its constructor parameter to the base class and does not use it. Otherwise the compiler reports CS9107, because the class would capture the parameter and also pass it on. In the four test classes below, change every use of `factory` in the test bodies to `Factory`. The assertions do not change.

## Step 3. Share one collection and one PostgreSQL container

Each test class still starts its own container, because each one declares its own class fixture. A collection shares one factory across the classes. We define the collection, remove the class fixture from the base class, and add the `Collection` attribute to every Catalog test class. The two classes from lessons 2.4 and 2.5 join too, so they do not start a second container. This step changes no behavior.

The collection definition is a new class. Its name must not end in `Collection`, because the analyzer rule CA1711 rejects that. The CLI creates the file, and we replace its content.

Run from the repository root:

```powershell
dotnet new class -n CatalogCollectionDefinition -o tests/Services/Catalog/BrickShare.Catalog.Api.Tests
```

`tests/Services/Catalog/BrickShare.Catalog.Api.Tests/CatalogCollectionDefinition.cs` (replace the template file with this content)

```csharp
using Xunit;

namespace BrickShare.Catalog.Api.Tests;

[CollectionDefinition(CatalogCollectionDefinition.Name)]
public sealed class CatalogCollectionDefinition : ICollectionFixture<CatalogApiFactory>
{
    public const string Name = "Catalog";
}
```

The base class no longer declares a class fixture. The collection provides the factory, and xUnit passes it to the constructor of each test class.
