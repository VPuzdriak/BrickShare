# Lesson 2.10. `InventoryCode` value object: alphabet, scramble, check character, parsing, test-first

Features: [F01](../features/01-catalog-management.md#inventory-code-and-qr-label)
Previous: [2.9](2.9-submit-set-from-rebrickable-draft.md) · Next: 2.11 Add instances: sequence, quantity, condition and physical status changes

## Summary

We build the `InventoryCode` value object in the Catalog Domain. It generates a code from a sequence number, with a scramble so that neighboring boxes get unrelated codes, and a check character that catches typing errors. It also parses a code that a person types or a scanner sends, and rejects a wrong code. At the end the Domain tests for the code are green. No table, endpoint, or sequence query is added yet.

## The problem

Each physical copy of a set needs an inventory code. The code goes on the label, and staff type or scan it to find the copy. [Catalog management](../features/01-catalog-management.md#inventory-code-and-qr-label) sets these rules:

> The code uses only characters that stay distinguishable when the label is scratched, faded, or partly torn.

The allowed characters are `2 3 4 5 7 9 A E H K M N P T W X Y`: 17 characters. The code is 5 characters plus 1 check character, printed as `W9X-25W`.

> Neighboring boxes look different. Copies of the same set stand next to each other on the shelf, so consecutive numbers must not give similar codes.

The feature doc gives the scramble. Number `n` becomes `m = (n × 738457) mod 17^5`, and `m` is written in base 17 with the alphabet. The examples in the doc are `1 → HW9-5N4`, `2 → 2NM-E94`, and `3 → KHX-MY3`. We use them as the first red test.

The check character is a Luhn mod 17 sum over the code. It catches a single wrong character or two swapped characters when a person types a code. A wrong code is rejected before any lookup. Input is normalized: lowercase is accepted, and dashes and spaces are ignored.

Before this lesson nothing in the Domain knows about inventory codes. The lesson introduces three things:

- **A value object with a checked constructor.** `InventoryCode` has a private constructor. The two ways in are `FromSequence` (the code is generated) and `Parse` (the code comes from a person or a scanner). `Parse` returns a `Result<InventoryCode>`, the same way `RebrickableSetNumber.Parse` does in lesson 2.8b. A value object is immutable and equal by its value, so the record type fits.
- **Pure encoding.** `FromSequence` takes a number and returns a code. It reads no database and no clock. The next number comes from the PostgreSQL sequence in lesson 2.11, which passes it in. That keeps the rule in the Domain and the sequence in the Api project.
- **Rules as tests first.** Each rule in the feature doc becomes one red test, then the smallest code that passes it.

What this lesson does not do:

- It does not read the PostgreSQL sequence `inventory_code_seq`. That is lesson 2.11.
- It does not add the `SetInstance` aggregate or any endpoint.
- It does not print the label. QR labels are lesson 2.12.
- It does not support the 6-character length. The parser accepts 6 or 7 characters in total, so labels stay valid if the length grows. `FromSequence` uses only the 5-character length.

## Step 3. Green: the alphabet, the scramble, base-17 encoding, and the check character

`src/Services/Catalog/BrickShare.Catalog.Domain/InventoryCode.cs` (replace the template class with this content)

```csharp
namespace BrickShare.Catalog.Domain;

public sealed record InventoryCode
{
    private const string Alphabet = "234579AEHKMNPTWXY";
    private const int Radix = 17;
    private const int CodeLength = 5;
    private const long Capacity = 1_419_857;
    private const long Multiplier = 738_457;

    private InventoryCode(string value)
    {
        Value = value;
    }

    public string Value { get; }

    public static InventoryCode FromSequence(long number)
    {
        var scrambled = number * Multiplier % Capacity;
        var body = Encode(scrambled);

        return new InventoryCode(body + CheckCharacter(body));
    }

    private static string Encode(long scrambled)
    {
        var digits = new char[CodeLength];
        var remaining = scrambled;

        for (var position = CodeLength - 1; position >= 0; position--)
        {
            digits[position] = Alphabet[(int)(remaining % Radix)];
            remaining /= Radix;
        }

        return new string(digits);
    }

    private static char CheckCharacter(string body)
    {
        var sum = 0;
        var factor = 2;

        for (var position = body.Length - 1; position >= 0; position--)
        {
            var addend = factor * Alphabet.IndexOf(body[position]);
            sum += addend / Radix + addend % Radix;
            factor = factor == 2 ? 1 : 2;
        }

        return Alphabet[(Radix - sum % Radix) % Radix];
    }
}
```

The constants are the values from the feature doc. `Capacity` is 17^5. `Multiplier` is 738457, and it has no common factor with 17, so every number in the range gets its own scrambled value.

`Encode` writes the scrambled value in base 17, from the last digit to the first, padded to 5 characters with the first alphabet character.

`CheckCharacter` is the Luhn mod 17 sum. It starts at the last character of the body with factor 2 and alternates between 2 and 1. Each product is split into its quotient and remainder by 17, and the parts are added. The check character is the one that brings the sum to a multiple of 17. The body `HW95N` gives sum 49, so the check index is 2, and that is `4`.

## Step 12. Green: `IsValid` checks the check character

The check character is computed from the code without its last character, with the same `CheckCharacter` method that `FromSequence` uses. The code is valid when the computed character equals the last one. The `&&` operator runs the check last, so a bad length or alphabet never reaches `CheckCharacter`.

`src/Services/Catalog/BrickShare.Catalog.Domain/InventoryCode.cs` (replace `IsValid`)

Before:

```csharp
    private static bool IsValid(string value) =>
        value.Length is 6 or 7
        && value.All(character => Alphabet.Contains(character));
```

After:

```csharp
    private static bool IsValid(string value) =>
        value.Length is 6 or 7
        && value.All(character => Alphabet.Contains(character))
        && CheckCharacter(value[..^1]) == value[^1];
```
