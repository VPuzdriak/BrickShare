# Lesson 5.2. Profile update, staff customer search

Features: [F03](../features/03-customer-accounts.md)
Previous: [5.1](5.1-customer-service-projects-and-provisioning.md) · Next: 5.3 Bans in the `Customer` aggregate: ban, lift, automatic ban, test-first

## Summary

We add two endpoints to the Customer Service. `PUT /customers/me` lets a customer change the display name and the phone number. The rules sit in the `Customer` aggregate, which returns a `Result` when a rule fails. `GET /customers?search` lets an employee or an admin find customers by part of the name or the e-mail address, ignoring case. At the end the Domain tests and the Api tests are green.

## The problem

Lesson 5.1 creates the customer on the first call and returns the profile. Customers cannot change it, and staff cannot find a customer. [F03](../features/03-customer-accounts.md) names both endpoints:

| Method | Route | Policy | Purpose |
|--------|-------|--------|---------|
| PUT | `/customers/me` | `CustomerOnly` | Update profile |
| GET | `/customers?search` | `EmployeeOrAdmin` | Find customers |

The feature doc and the architecture set these rules:

- "The user id is always the `oid` claim. Customer-facing endpoints never take a customer id from the route. They read it from the token." ([F03](../features/03-customer-accounts.md))
- "On the first call with a valid customer token, the service creates the `Customer` record." ([F03](../features/03-customer-accounts.md)). The update endpoint is a first call too, so it creates the customer as well.
- The `Customer` model has `DisplayName` and `Phone`. ([Architecture 3.6](../Architecture.md#36-customer-service))
- "Business rules live in aggregates and value objects, not in endpoints or handlers." ([CLAUDE.md](../../CLAUDE.md))

F03 names the endpoints but gives no field rules. This lesson takes the fields from the `Customer` model and sets the limits below. The limits are choices, not doc rules.

Concepts we introduce:

- **Behavior on the aggregate.** `Customer.UpdateProfile` checks the rules and changes the state. There are no public setters. The handler loads the customer, calls the method, and saves.
- **Results instead of exceptions.** A failed rule returns a `Result` with a `DomainError`. The handler maps the error to `ProblemDetails`. This is the pattern from [Architecture 7.1](../Architecture.md#71-domain-driven-design).
- **Two route groups with one prefix.** `/customers` gets a second group with the `EmployeeOrAdmin` policy. Each group declares one policy, as [CLAUDE.md](../../CLAUDE.md) requires.
- **Parameterized search with `ILIKE`.** The search runs in PostgreSQL. The search text is escaped, so `%` and `_` match only themselves.

Scope decisions for this lesson:

- **The e-mail address does not change.** The e-mail address is the sign-in identity from External ID. The profile update changes only the display name and the phone number.
- **Field limits.** The display name is required after trimming, and it has at most 100 characters. The phone number is optional, and it has at most 32 characters. A blank phone number is stored as no phone number. The update replaces both fields, so a request without a phone number clears it.
- **Rules in the aggregate, not in a validator.** The service has two field rules, both of which belong to the profile. They live in the aggregate. The Catalog Service uses FluentValidation for request shape. This service does not add it yet.
- **Search returns at most 50 customers.** The search text is required. The results are sorted by name, with no paging. The feature doc does not set a limit, so this lesson sets one.
- **No ban status and no events.** Lesson 5.3 adds the ban status. `CustomerRegistered` still waits for the outbox in module 7.
- **The host does not change.** `Program.cs` already registers the `DbContext`, the clock, and the authentication.

```csharp
    public Result UpdateProfile(string? displayName, string? phone)
    {
        var name = displayName?.Trim() ?? string.Empty;
        var number = string.IsNullOrWhiteSpace(phone) ? null : phone.Trim();

        if (name.Length == 0)
        {
            return Result.Failure(DisplayNameRequired);
        }

        if (name.Length > MaxDisplayNameLength)
        {
            return Result.Failure(DisplayNameTooLong);
        }

        if (number?.Length > MaxPhoneLength)
        {
            return Result.Failure(PhoneTooLong);
        }

        DisplayName = name;
        Phone = number;

        return Result.Success();
    }
```

```csharp
using System;
using System.Security.Claims;
using System.Threading;
using System.Threading.Tasks;

using BrickShare.Customers.Api.Infrastructure.Identity;
using BrickShare.Customers.Api.Infrastructure.Persistence;
using BrickShare.Customers.Domain;

using Microsoft.EntityFrameworkCore;

namespace BrickShare.Customers.Api.Features.Customers;

public static class CurrentCustomer
{
    public static async Task<Customer> LoadOrCreateAsync(
        ClaimsPrincipal user,
        CustomerDbContext dbContext,
        TimeProvider timeProvider,
        CancellationToken cancellationToken)
    {
        var customerId = user.CustomerId();

        var customer = await dbContext.Customers.FirstOrDefaultAsync(
            candidate => candidate.Id == customerId, cancellationToken);

        if (customer is not null)
        {
            return customer;
        }

        customer = new Customer(
            customerId,
            user.FindFirst("email")?.Value ?? string.Empty,
            user.FindFirst("name")?.Value ?? string.Empty,
            timeProvider.GetUtcNow());

        dbContext.Customers.Add(customer);
        await dbContext.SaveChangesAsync(cancellationToken);

        return customer;
    }
}
```

## Step 9. Green: the staff customer search

The search endpoint lives in the same service under `/customers`. It needs the `EmployeeOrAdmin` policy, not `CustomerOnly`. So it gets its own route group with the same prefix. Each group declares its own policy.

The search text is escaped before it goes to `ILIKE`. The helper escapes the backslash first, then `%` and `_`. We pass the backslash to `EF.Functions.ILike` as the escape character. The two-argument overload does not work here: the Npgsql provider sends `ESCAPE ''` for it, which turns escaping off. A search for `100%` then matches the text `100%` and nothing else.

```csharp
using System;
using System.Collections.Generic;
using System.Linq;
using System.Threading;
using System.Threading.Tasks;

using BrickShare.Customers.Api.Infrastructure.Persistence;

using Microsoft.AspNetCore.Builder;
using Microsoft.AspNetCore.Http;
using Microsoft.AspNetCore.Http.HttpResults;
using Microsoft.AspNetCore.Routing;
using Microsoft.EntityFrameworkCore;

namespace BrickShare.Customers.Api.Features.Customers.SearchCustomers;

public static class SearchCustomers
{
    private const int MaxResults = 50;
    private const string EscapeCharacter = "\\";

    public static void MapSearchCustomers(this RouteGroupBuilder customers) =>
        customers.MapGet("/", Handle);

    private static async Task<Results<Ok<List<CustomerSummaryResponse>>, ProblemHttpResult>> Handle(
        string? search,
        CustomerDbContext dbContext,
        CancellationToken cancellationToken)
    {
        var term = search?.Trim();

        if (string.IsNullOrEmpty(term))
        {
            return CustomerProblems.SearchTextRequired();
        }

        var pattern = $"%{EscapeLike(term)}%";

        var customers = await dbContext.Customers
            .Where(customer => EF.Functions.ILike(customer.DisplayName, pattern, EscapeCharacter)
                || EF.Functions.ILike(customer.Email, pattern, EscapeCharacter))
            .OrderBy(customer => customer.DisplayName)
            .ThenBy(customer => customer.Email)
            .Take(MaxResults)
            .Select(customer => new CustomerSummaryResponse(customer.Id, customer.Email, customer.DisplayName))
            .ToListAsync(cancellationToken);

        return TypedResults.Ok(customers);
    }

    private static string EscapeLike(string term) =>
        term.Replace("\\", "\\\\", StringComparison.Ordinal)
            .Replace("%", "\\%", StringComparison.Ordinal)
            .Replace("_", "\\_", StringComparison.Ordinal);
}
```

The search matches the display name or the e-mail address. The results are sorted by name, and at most 50 come back.
