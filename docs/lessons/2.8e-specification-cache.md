# Lesson 2.8e. Adapter: 24-hour in-memory cache, test-first

Features: [F01](../features/01-catalog-management.md#lookup-in-rebrickable)
Previous: [2.8d](2.8d-unknown-set-returns-null.md) · Next: [2.8f](2.8f-rebrickable-unavailable-domain-exception.md)

## Summary

The adapter keeps each found set for 24 hours in `IMemoryCache`. A repeated lookup makes no call to Rebrickable. Unknown sets are not cached, so a set that Rebrickable adds later is found at once. At the end the adapter has three green tests.

## The problem

[Architecture.md section 3.2](../Architecture.md#32-catalog-service) says: "Responses are cached in memory for 24 hours, and calls are kept under Rebrickable's rate limit." Lookups are admin actions, and the admin often looks up the same set twice. The cache saves calls and keeps the lookup quick.

## Step 3. Green: cache the specification for 24 hours

The adapter takes an `IMemoryCache`. The test helper passes a real cache, and each test gets its own, so tests do not share results. The shared framework includes `Microsoft.Extensions.Caching.Memory`, so the test project needs no package.

`src/Services/Catalog/BrickShare.Catalog.Api/Infrastructure/Rebrickable/RebrickableSetSpecificationProvider.cs` (replace the class declaration and add the duration; add `using Microsoft.Extensions.Caching.Memory;` at the top)

Before:

```csharp
public sealed class RebrickableSetSpecificationProvider(HttpClient httpClient) : ISetSpecificationProvider
{
    private static readonly JsonSerializerOptions JsonOptions = new()
```

After:

```csharp
public sealed class RebrickableSetSpecificationProvider(HttpClient httpClient, IMemoryCache cache) : ISetSpecificationProvider
{
    private static readonly TimeSpan CacheDuration = TimeSpan.FromHours(24);

    private static readonly JsonSerializerOptions JsonOptions = new()
```

`src/Services/Catalog/BrickShare.Catalog.Api/Infrastructure/Rebrickable/RebrickableSetSpecificationProvider.cs` (replace the whole `FindAsync` method)

```csharp
    public async Task<SetSpecification?> FindAsync(RebrickableSetNumber setNumber, CancellationToken cancellationToken)
    {
        if (cache.TryGetValue(setNumber.Value, out SetSpecification? cached))
        {
            return cached;
        }

        var setResponse = await GetAsync<SetResponse>($"api/v3/lego/sets/{setNumber.Value}/", cancellationToken);

        if (setResponse is null)
        {
            return null;
        }

        var minifigs = await GetRequiredAsync<MinifigsResponse>($"api/v3/lego/sets/{setNumber.Value}/minifigs/", cancellationToken);
        var theme = await LoadThemeAsync(setResponse.ThemeId, cancellationToken);

        var specification = new SetSpecification(
            setNumber,
            setResponse.Name,
            setResponse.Year,
            setResponse.NumParts,
            minifigs.Count,
            theme,
            setResponse.SetImgUrl is null ? null : new Uri(setResponse.SetImgUrl),
            new Uri(setResponse.SetUrl));

        cache.Set(setNumber.Value, specification, CacheDuration);

        return specification;
    }
```

Only found sets are cached. The `null` for an unknown set returns before the cache write.

The test helper passes a real cache.

`tests/Services/Catalog/BrickShare.Catalog.Api.Tests/RebrickableSetSpecificationProviderTests.cs` (replace the `CreateProvider` method, and add `using Microsoft.Extensions.Caching.Memory;` at the top)

Before:

After:
