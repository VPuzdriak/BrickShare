# Lesson 5.4. Ban endpoints

Features: [F05](../features/05-customer-bans.md)
Previous: [5.3](5.3-bans-in-the-customer-aggregate.md) · Next: 5.5 Staff management: `IStaffDirectory` port, Microsoft Graph adapter, app role assignment

## Summary

We expose the ban rules from lesson 5.3 as two admin endpoints: `POST /customers/{id}/bans` and `DELETE /customers/{id}/bans/{banId}`. The bans are stored in a `customer_bans` table, and the `status` column of `customers` follows them. At the end an admin can ban a customer and lift the ban over HTTP. The integration tests check the response and the stored state.

## The problem

The `Customer` aggregate can ban and lift, but nothing calls it yet. [F05](../features/05-customer-bans.md) names the endpoints and the policy:

| Method | Route | Policy | Purpose |
|--------|-------|--------|---------|
| POST | `/customers/{id}/bans` | `AdminOnly` | Ban customer |
| DELETE | `/customers/{id}/bans/{banId}` | `AdminOnly` | Lift ban |

Two things are missing:

- **No storage.** Lesson 5.3 ignores `Status` and `Bans` in EF Core, so no ban is saved. The `customers` table has no `status` column, and there is no table for bans.
- **No HTTP mapping.** The aggregate returns `DomainError` values with stable codes, such as `customer.ban_not_found`. The API must turn each one into a status code.

Rules that drive the lesson, quoted from F05:

- "A ban has a reason (`LateReturn`, `NonReturn`, `Neglect`, `NonPayment`, `Other`), a comment, who banned, from, until (null = permanent), and lifted at."
- "Banned customers cannot create reservations." This is not built in this lesson. It comes with the Reservation module.

The ban endpoints are staff endpoints. F05 puts the customer id in the route, so the route id is correct here. The rule "customer endpoints never take a customer id from the route" still holds for `/customers/me`. The admin's id comes from the token. [CLAUDE.md](../../CLAUDE.md) says so: "Customer and staff ids come from the `oid` token claim."

Choices in this lesson. F05 gives the routes, the policy, and the rules. It does not give HTTP status codes or the JSON shape. These choices are ours:

- **`POST` returns `201 Created`** with the new ban. The `Location` header names the ban's path, `/customers/{id}/bans/{banId}`. That path has no `GET` yet. Its `DELETE` is the lift endpoint.
- **`DELETE` returns `204 No Content`.**
- **Failures:** an unknown customer gives `404`. An unknown ban gives `404`. A ban that is already lifted gives `409 Conflict`. A rule the aggregate rejects gives `400`. All failures return RFC 9457 `ProblemDetails`.
- **`bannedBy` is the admin's `oid`.** It is a string, as in lesson 5.3.
- **The reason is a JSON string**, such as `"LateReturn"`. The project had no string enum setting before this lesson, so we add one for the `Customers` API.
- **No events yet.** F05 lists `CustomerBanned` and `CustomerUnbanned`. The outbox and the event lessons come in module 7. Lesson 7.5 maps the domain events to integration events, so this lesson publishes nothing.

Concepts we introduce:

- **An owned collection.** EF Core stores the `Ban` entities as children of `Customer`. They have no table of their own. They get a `customer_bans` table with a foreign key to `customers`.
- **A `Result<T>` with the new value.** `AddBan` returns the ban it added, so the endpoint can return it. The caller does not search the list for it.
- **Stable error codes mapped to status codes.** The API compares a `DomainError` with the public error values in `Customer`. It does not parse messages.

## Step 6. Green, part 1: map the aggregate to the database

Now the storage. The `customers` table gets a `status` column, and a new `customer_bans` table holds the bans. The mapping removes the two `Ignore` lines from lesson 5.3.

Three details in the mapping:

- `Status` is stored as text, so the table reads `Active` or `Banned`, not `0` or `1`.
- `Status` gets a database default of `'Active'`. Existing customer rows already exist in a development database, and a column without a default would fail on them.
- `Bans` is an owned collection. `WithOwner().HasForeignKey("customer_id")` links each row to its customer. The key is the ban `Id`. EF Core reads and writes the list through the backing field `_bans`.

`src/Services/Customers/BrickShare.Customers.Api/Infrastructure/Persistence/CustomerConfiguration.cs` (replace the file with this content)

```csharp
using BrickShare.Customers.Domain;

using Microsoft.EntityFrameworkCore;
using Microsoft.EntityFrameworkCore.Metadata.Builders;

namespace BrickShare.Customers.Api.Infrastructure.Persistence;

public sealed class CustomerConfiguration : IEntityTypeConfiguration<Customer>
{
    public void Configure(EntityTypeBuilder<Customer> builder)
    {
        builder.ToTable("customers");

        builder.HasKey(customer => customer.Id);

        builder.Property(customer => customer.Id)
            .ValueGeneratedNever()
            .HasColumnName("id");

        builder.Property(customer => customer.Email)
            .HasColumnName("email");

        builder.Property(customer => customer.DisplayName)
            .HasColumnName("display_name");

        builder.Property(customer => customer.Phone)
            .HasColumnName("phone");

        builder.Property(customer => customer.CreatedAt)
            .HasColumnName("created_at");

        builder.Property(customer => customer.Status)
            .HasColumnName("status")
            .HasConversion<string>()
            .HasDefaultValueSql("'Active'");

        builder.OwnsMany(customer => customer.Bans, ban =>
        {
            ban.ToTable("customer_bans");
            ban.WithOwner().HasForeignKey("customer_id");
            ban.HasKey(item => item.Id);

            ban.Property(item => item.Id)
                .ValueGeneratedNever()
                .HasColumnName("id");

            ban.Property(item => item.Reason)
                .HasConversion<string>()
                .HasColumnName("reason");

            ban.Property(item => item.Comment)
                .HasColumnName("comment");

            ban.Property(item => item.BannedBy)
                .HasColumnName("banned_by");

            ban.Property(item => item.From)
                .HasColumnName("banned_from");

            ban.Property(item => item.Until)
                .HasColumnName("banned_until");

            ban.Property(item => item.LiftedAt)
                .HasColumnName("lifted_at");

            ban.Ignore(item => item.IsActive);
        });

        builder.Ignore(customer => customer.DomainEvents);
    }
}
```

```csharp
using System;
using System.Security.Claims;
using System.Threading;
using System.Threading.Tasks;

using BrickShare.Customers.Api.Infrastructure.Identity;
using BrickShare.Customers.Api.Infrastructure.Persistence;

using Microsoft.AspNetCore.Builder;
using Microsoft.AspNetCore.Http;
using Microsoft.AspNetCore.Http.HttpResults;
using Microsoft.AspNetCore.Routing;

namespace BrickShare.Customers.Api.Features.Customers.BanCustomer;

public static class BanCustomer
{
    public static void MapBanCustomer(this RouteGroupBuilder customers) =>
        customers.MapPost("/{id:guid}/bans", Handle);

    private static async Task<Results<Created<BanResponse>, ProblemHttpResult>> Handle(
        Guid id,
        BanCustomerRequest request,
        ClaimsPrincipal user,
        CustomerDbContext dbContext,
        TimeProvider timeProvider,
        CancellationToken cancellationToken)
    {
        var customer = await dbContext.Customers.FindAsync([id], cancellationToken);

        if (customer is null)
        {
            return CustomerProblems.CustomerNotFound(id);
        }

        var result = customer.AddBan(
            request.Reason,
            request.Comment,
            user.StaffId(),
            request.Until,
            timeProvider.GetUtcNow());

        if (result.Error is { } error)
        {
            return CustomerProblems.InvalidBan(error);
        }

        await dbContext.SaveChangesAsync(cancellationToken);

        var ban = result.Value;

        return TypedResults.Created($"/customers/{id}/bans/{ban.Id}", BanResponse.Map(ban));
    }
}
```

```csharp
using System;
using System.Threading;
using System.Threading.Tasks;

using BrickShare.Customers.Api.Infrastructure.Persistence;
using BrickShare.Customers.Domain;

using Microsoft.AspNetCore.Builder;
using Microsoft.AspNetCore.Http;
using Microsoft.AspNetCore.Http.HttpResults;
using Microsoft.AspNetCore.Routing;

namespace BrickShare.Customers.Api.Features.Customers.LiftBan;

public static class LiftBan
{
    public static void MapLiftBan(this RouteGroupBuilder customers) =>
        customers.MapDelete("/{id:guid}/bans/{banId:guid}", Handle);

    private static async Task<Results<NoContent, ProblemHttpResult>> Handle(
        Guid id,
        Guid banId,
        CustomerDbContext dbContext,
        TimeProvider timeProvider,
        CancellationToken cancellationToken)
    {
        var customer = await dbContext.Customers.FindAsync([id], cancellationToken);

        if (customer is null)
        {
            return CustomerProblems.CustomerNotFound(id);
        }

        var result = customer.LiftBan(banId, timeProvider.GetUtcNow());

        if (result.Error is { } error)
        {
            return error == Customer.BanNotFound
                ? CustomerProblems.BanNotFound(banId)
                : CustomerProblems.BanAlreadyLifted(banId);
        }

        await dbContext.SaveChangesAsync(cancellationToken);

        return TypedResults.NoContent();
    }
}
```
