# Lesson 1.6. Shared kernel: `Entity`, `AggregateRoot`, domain events, results

Previous: [1.5](1.5-test-projects-with-xunit-and-awesomeassertions.md) · Next: 1.7 `Money` value object, test-first

## Summary

We create the first real projects: `BrickShare.SharedKernel` and its test project `BrickShare.SharedKernel.Tests`. We write each type test-first, so every rule has a failing test before its code. At the end the shared kernel has `Entity<TId>`, `AggregateRoot<TId>`, `IDomainEvent`, `DomainError`, `Result`, and `Result<T>`, and nine tests pass.

## The problem

The repository has build rules, code style, and a test stack, but no domain code. Nothing yet defines what an entity is, what an aggregate does, or how a business failure is reported. Without shared types, each service would write its own version, and the rules would drift:

- **Identity.** Two reservations with the same id are the same reservation. Without a shared rule, each aggregate chooses its own equality.
- **Events.** An aggregate records what happened, so a handler can later write an integration event to the outbox ([lesson 7.5](../CoursePlan.md)). Without a shared list, each aggregate builds its own.
- **Errors.** A business failure such as `InstanceNotBookable` is part of the rules. Without a shared type, some code throws and some returns a null.

The rules come from [Architecture.md section 7.1](../Architecture.md#71-domain-driven-design):

- Aggregates protect their invariants. State changes only through methods, never through public setters.
- Value objects are immutable records. They validate in the constructor.
- Domain events are raised by aggregates. They stay internal. Integration events in `BrickShare.Contracts` are the public contract.
- Errors that are part of the business are returned as results, not thrown.

No file in `docs/features/` drives this lesson. These types serve the features that follow. The tests therefore check the rules above. [Architecture.md section 7.2](../Architecture.md#72-testing-strategy-and-tdd) requires a fast unit test for each rule, with no mocks.

The concepts:

- **Entity.** A class with an identity, `Id`. Two entities are equal when their ids and their types match.
- **AggregateRoot.** An entity that is the entry point of a consistency boundary. It keeps the list of domain events that its methods raise.
- **IDomainEvent.** The marker interface for a domain event. Domain events are internal, so the type has no members.
- **Result.** The outcome of an operation that can fail for a business reason. It holds either a value or a `DomainError`.

The shared kernel is plain C#. It has no reference to ASP.NET Core, EF Core, or Azure. It lives in `src/BuildingBlocks/BrickShare.SharedKernel/` ([Architecture.md section 7](../Architecture.md#7-solution-structure)).

```csharp
using System.Collections.Generic;

namespace BrickShare.SharedKernel;

public abstract class AggregateRoot<TId>(TId id) : Entity<TId>(id)
    where TId : notnull
{
    private readonly List<IDomainEvent> _domainEvents = [];

    public IReadOnlyList<IDomainEvent> DomainEvents => _domainEvents.AsReadOnly();

    protected void Raise(IDomainEvent domainEvent) => _domainEvents.Add(domainEvent);
}
```

`DomainEvents` returns a read-only view, so the handlers that read it cannot change the aggregate.

```csharp
public sealed class Result
{
    private Result(DomainError? error)
    {
        Error = error;

    public DomainError? Error { get; }
```
