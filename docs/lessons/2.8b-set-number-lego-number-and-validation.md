# Lesson 2.8b. Rebrickable set number: LEGO set number and input validation

Features: [F01](../features/01-catalog-management.md#sets), [F01 lookup](../features/01-catalog-management.md#lookup-in-rebrickable)
Previous: [2.8a](2.8a-set-number-variants.md) · Next: 2.8c `ISetSpecificationProvider` port and Rebrickable adapter: set, minifigures and theme tree, stub-based tests

## Summary

We add two rules to `RebrickableSetNumber`. The LEGO set number is the part before the variant, so `10294-2` gives `10294`. Text that is not a set number returns a failure result instead of a reference. At the end all `RebrickableSetNumberTests` are green: three facts and five theory cases.

## The problem

[Catalog management](../features/01-catalog-management.md#sets) says:

> The LEGO set number is digits only. `10294-1` is not a LEGO set number: the `-1` suffix is part of the Rebrickable reference.

Lesson 2.8a adds `-1` to a number without a variant. It still accepts any text. An empty string, letters, a dash without a number, and two dashes all pass. The admin types this text by hand, and the lookup in lesson 2.8c sends the reference to Rebrickable. Bad input must stop in the domain, before any call.

We reuse `LegoSetNumber` from lesson 2.2. It rejects non-digits, but it throws an exception. A throw is the wrong result for user input. `RebrickableSetNumber.Parse` therefore checks the text first and returns a `Result` failure. The feature docs do not say what happens for bad input, so this lesson sets the rule: a failure result here, and `400` in lesson 2.8i.

## Step 5. Green: validate the text and return a failure

`Parse` splits the text at the dash. It accepts one part (no variant) or two parts (a variant). Each part must be non-empty and contain only digits. `char.IsAsciiDigit` is the same rule that `LegoSetNumber` uses. Any other text returns a failure with a `DomainError`. The error code follows the style of the shared kernel tests: `set.not_available`, so `set_number.invalid` here.

`src/Services/Catalog/BrickShare.Catalog.Domain/RebrickableSetNumber.cs` (add `using System.Linq;` above the existing `using BrickShare.SharedKernel;`, with a blank line between the two groups, as in `LegoSetNumber.cs`)

```csharp
using System.Linq;

using BrickShare.SharedKernel;
```

`src/Services/Catalog/BrickShare.Catalog.Domain/RebrickableSetNumber.cs` (replace the `Parse` method from lesson 2.8a. The check runs first, so the `LegoSetNumber` property never sees bad text)

```csharp
    public static Result<RebrickableSetNumber> Parse(string input)
    {
        var parts = input.Split('-');

        if (parts.Length is not (1 or 2) || parts.Any(part => part.Length == 0 || !part.All(char.IsAsciiDigit)))
        {
            return Result.Failure<RebrickableSetNumber>(new DomainError(
                "set_number.invalid",
                "A Rebrickable set number is digits, optionally followed by a dash and a variant number."));
        }

        var value = parts.Length == 1 ? input + DefaultVariant : input;

        return Result.Success(new RebrickableSetNumber(value));
    }
```
